# 对应记录判断：合成示例

以下企业、时间及流程均为合成教学示例，不是生产证据。判断由用户指定的业务代理完成；表格用于解释口径，不是软件自动判因规则。

| 情况 | 判断 | 保留与边界 |
|---|---|---|
| 甲企业某称号2023年正式认定，平台同批申请通过；2026年更新为“已退回待审核”，没有相反的正式结果。 | 历史与后续流程可对应时，无差异。 | 保留2023年认定和2026年退回原文；不因当前导出没有就制造历史差异，不凭无新公布认定失效。 |
| 乙企业某称号2026年第一批正式认定已公布，平台对应同一主体、称号、批次仍停在申请待审核。 | 平台未更新。 | 公布事实与同批流程尚未一致；不要求知道平台内部为什么没有更新。 |
| 丙企业历史认定和平台历史通过一致，后续更新待审核。 | 先按对应记录判断是否无差异；只有用户明确要求该批次另按待审核记录时才使用该差异分类。 | 待审核是流程状态，不是任何历史公布与最新导出不一致时的默认原因；之前明确批准的写入不被新口径静默覆盖。 |
| 丁企业复核终审不通过，随后又提交更新或新申请待审核。 | 分别保留复核结果和新流程，再与对应公布判断是否一致。 | 后来的提交不反转复核失败；流程失败本身也不自动成为公布差异。 |
| 戊企业有正式公布，三接口均完整查询且整户零行。 | 无记录，注明整户零。 | 若仅同称号零行则注明称号范围；分页失败或会话过期不属于无记录。保留正式历史。 |
| 己企业同一已确认主体的旧名关系记上海属地，新名关系记宁波属地，已有确认的旧名/搬迁证据。 | 迁入；同时记录有证据支持的更名。 | 原称号、批次、搬迁日期未知留空，不重查已有证明；仅有外地名称或信用代码前缀还不够。 |
| 庚企业更名已确认，平台2026年复核通过，但检查过的对应复核公布名单无该企业的新旧名。 | 更名事实保留；复核公布缺口列待人工审查。 | 不因更名成立而取消复核名单审查，不用旧认定文件替代新复核结果。 |
| 辛企业认定接口有新行，原导出未命中；原流程与公布的对应清楚，用户确认该阶段按未更新记录。 | 按用户确认归平台未更新，写清查询/快照时间与流程原文。 | 先排除文件版本、查询范围、表头及漏读；另一称号的导出命中不抵消本称号。若同称号原始行实际存在，纠正漏匹配。 |
| 壬企业平台认定有记录，正式来源中未找到能对应的文件。 | 待人工审查：缺对应公布依据。 | 与复核名单缺口、身份/属地冲突使用同一顶层分类，具体问题分别写清，不再用“事实不足”隐藏问题。 |

## 交付检查

- 每个结论都能指出对应的企业、称号、事件/流程类型、年份/批次及原始证据位置；不能用最新状态概括整段历史。
- 统计分别给出企业数和称号/事件项数，说明跨类重叠；人工审查问题有具体名称、记录及缺失事实。
- 报告生成、业务判断、预检、提交、读回分开报告。只有实际提交并读回才称已入库。
- 真实个案、业务单号、原始证据与运行计数保存在 Git 外；以上示例不替代任何实际个案核验。
