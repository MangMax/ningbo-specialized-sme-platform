# 多代理编排

## 协调者与工作者

接到完整文件/企业清单、没有被指定具体工作片的执行者，负责本轮协调；它本身由父代理委派也不改变此职责。协调者先确定范围和资源预算，再决定直接处理或分派。已领取具体文件/页段/企业工作片的代理为工作者，不继续拆派；同企业跨称号只有一名负责人。

有多个独立工作片且可用资源允许时，协调者使用委派工具启动有界工作者池，自己只做分组、交接、处理冲突和汇总；不先独自调查完整清单再考虑分派。仅有少量轻任务、依赖尚未满足或没有并行余量时可以直接处理，记明实际选择。工具不可用、平台禁止嵌套或资源不足时如实降级，不把单代理的并发搜索说成多代理编排。

## 全流程资源预算

**队列长度、工作片大小、活跃代理数是三个独立参数。**几百或上千项放入持久队列，由有限工作者分波次领取；不会因为每片几项就同时创建几百名代理。

以下为无其他配置时的保守起点，均是整轮共享额度，服务端限制更低时服从较低值：

| 资源 | 初始安排与边界 |
|---|---|
| 活跃工作代理（全部阶段合计） | 从 2 名开始，有空闲且吞吐改善时逐步调至 4 名；默认最多 4 名，最多 1 名协调者另计。已有其他任务占用时扣减；数量不随企业/文件总数线性增长。提高上限须有用户资源预算或可观测余量，不能因队列长自行突破。 |
| 本机转图/大文件解析 | 先 1 个重任务，内存与 CPU 有余量时最多 2 个；它们同时占本轮工作者和本机资源预算。 |
| OCR 在途页请求 | 先 2 个，服务与机器有余量时逐步增加，默认最多 4 个；不是每名代理各有 4 个。 |
| 公开搜索/抓取请求 | 整轮先 2 个在途请求，额度与响应稳定时最多 4 个；异步请求照样占额度。 |
| 平台实时请求 | 应用全进程最多 2 个，包括各工作者、单查、批量和退避；多应用实例不能各自翻倍。 |
| 业务写入者 | 全批 1 名；同企业变更串行、API 预检/提交/读回，沿用幂等键。 |
| 独立验收读取者 | 默认 1 名，占全流程工作者名额；按文件/企业/ID 范围读取，避免全表原始大字段加载。 |

代理名额与工具额度同时满足才开始工作，不能把各阶段上限相加后全部开满。其他线程、Docker、OCR 子进程和浏览器都占宿主资源。协调者在启动前及每波完成时看可用代理名额、可取得的内存/CPU/磁盘余量、应用延迟、限流与失败比例；不可取得的指标记未知，保持保守额度，不编造“资源充足”。已有应用内存、SQLite 或共享文件系统事故时采用当前部署限制。

资源紧张、429、排队变长或应用响应恶化时，暂停领取新任务、减少在途请求或活跃名额；保留已完成结果和检查点，等待后继续。只有前一波正常、下游无积压且扩容确实改善吞吐时才每次增加一个名额。不可通过加代理掩盖服务瓶颈。

## 工作片大小与调度

1. **先建立轻量清单**：按文件/页数、稳定企业 ID、关系行数、证据体积、待补查询和已完成状态估计工作量。清单与完整原档分开，按需读取原文，不把数百家全部原始响应灌进每名代理上下文；脚本只做索引/投影/统计，不自动判原因。
2. **首片校准**：使用少量有代表性的轻/重项观察启动成本、处理时长、请求数和上下文占用。已有相同任务的可靠实测可直接复用，不强制重复试跑。首片即正式产出，成功项不重做。
3. **按实际工作量切片**：以约数分钟内可交付、可独立恢复的工作片为起点，按每项实测成本及上下文容量增减项数。单项很轻可一片十几至数十项，关系复杂时缩为几项或一项；这些是示例，不是每代理固定 3 家或每批固定大小。每片只传清单、索引和必要上下文，逐项读取证据、增量落盘。
4. **有限在途、分波次领取**：活跃任务不超过预算，每名工作者一次领取一片；只预备少量下一片，不预先启动整队列。空闲后续领下一片，能复用上下文时复用，接近上下文/内存边界时在检查点更换代理。不能把已承载完整队列的代理再挂多层协调者。
5. **轻重分流与背压**：遇到额外身份候选、复杂冲突或工具故障时保存当前依据，把疑难单元交独立队列；先完成普通项。下游纠偏/核验/写入积压时，限制上游转图、OCR 或新调查，待下游释放容量再补充；某文件就绪即交接，不等待整批全部结束。
6. **记录实际选择**：在已有批次清单记录待处理/在途/已完成/待核/失败、负责人、片范围、资源额度和调整原因。工作者交一份结构化结果，协调者统一报告；不要求每项重复写 JSON、Markdown 和多份汇总。

### 按规模选择，而非按总数增加代理

| 实际任务 | 合理安排示例 |
|---|---|
| 几家且证据很少 | 直接完成，或 1–2 名工作者；启动开销高于收益时不拆。 |
| 十几家、各有独立查证 | 在资源预算内分数片并行；依据关系行数分配，不机械平均。 |
| 四百家、上千家 | 仍用同一个有限工作者池，按首片实测形成合适大小的工作片，持续领取、分波次落盘；只有需要判断的项进判断队列，已有确认或无差异项按本轮范围复用。 |
| 大量 PDF 页图 | 有界转图/OCR队列，按页保存、按文件交接；不每页建一个代理，不把全部高分辨率图片同时驻留内存。 |

## 各环节如何共用调度

| 阶段 | 工作单元与约束 |
|---|---|
| 文件分类/文字解析 | 按文件大小和复杂度打包；轻文件可一片多个，大文件独立，分类完成项立即流向后续。 |
| 转图/OCR | 文件负责人在共享请求额度内提交多个文件、多个页图；有界生产页图，保存后释放内存。成功页不因别页失败重跑。 |
| 纠偏/视觉核验 | 按文件及页段分片，保留每行页号与完整覆盖；独立核验者不核验自己的修改，工作者池为其保留容量。 |
| 身份/平台采集/差异判断 | 同企业跨称号归并，复用三接口与公开依据；调查工作者可以并行，平台网络只走共享应用队列。 |
| 预检/写入/读回 | 载荷准备可分片，批准后的提交由唯一写入者执行；批量大小受在线契约、字节数和恢复成本限制，不由企业总数决定。 |
| 验收/报告/失败恢复 | 按已完成片增量核验并汇总，覆盖全部范围；疑难项不算完成，失败只重试原单元，保留成功回执。 |

## 判断任务的范围与效率

- 判断使用用户指定的 Magpie + DeepSeek Open Design、high 思考程度。协调者也受负载预算约束，不重复工作者全部调查。
- 单企常规判断以不超过 1 分钟为效率目标；小批任务以约 3–5 分钟交付为目标，疑难单元及时交接。它们不是数百或上千项整批完成的时限，也不是放宽证据的理由。大批首片后按剩余工作量、实际吞吐和瓶颈估算时间，定期交付进度；10 分钟仍无结果或进展时检查调度/工具瓶颈，而非盲目加代理。
- 只调查本轮要决定的事实。迁移判断聚焦主体、名称沿革和方向；日期、详细地址等非必需字段留空，不扩展到全部称号、公告或重复文件核查。
- 交接归档时同时提供按接口投影的名称/区县/行 ID 清单和各接口原行总数，保留原档以便回查；工作者核对覆盖范围后再搜索。实测开始时间取开始执行时的时钟，不能用输入目录创建时间代替；缺少精确计时就标估计。
- 原页反爬不反复抓同一网址；改用精确名称、信用代码或另一引擎补缺口。事实已支持结论即收口，明确冲突才追加定向查询。

## 分工与复用证据

- 每份源文件一名负责人。该文件 OCR 就绪即交纠偏；其他文件可继续转图或使用共享 OCR 队列。
- OCR 就绪交接须有每页结果或明确失败；缺任一页即标部分完成，不把缺页算已完成。
- 每家企业跨文件、跨称号只设一名调查者，并向文件负责人共享相同 batchId/itemId。按企业 ID 分组；尚无 ID 时按已确认信用代码分组。同一企业各文件行共用一份证据日志。
- 同名但未确认 ID 的结果仍为候选。不同候选主体分开保存，不能只因名称相同共享身份决定或合并。
- 每批一名写入者，同一企业变更串行执行，即使证据来自不同文件。独立验收者接收完整证据包，不编辑该批载荷。

## 先判断，后写入

- 明确用户指定的判断组合。要求 Magpie + DeepSeek Open Design 时，业务判断使用该组合；实施/运维代理整理事实、准备 API 载荷、部署并执行确认后的写入。脚本只索引、比对原始事实和统计，不用原因映射规则替代代理。
- 交给判断代理的材料包含用户当前口径、相关正式事件、三个归档接口、准确导出版本及既有确认身份/迁入证据。复用完整证据；用户限定已有证据时，不扩大到公开/PDF 查证或重查全量。
- 判断代理逐案给出决定后，写入者才提交批次。已批准、未解决、排除项分别保存；代码验收或预检成功不等于业务确认。只做报告的授权不变成提交授权。
- 若先写入后判断，如实说明顺序并安排事后确认，不能把事后确认说成写前批准；更正仍走授权 API，并保留旧审计。
- 按稳定企业/称号/事件范围合并报告，不按代理私有标签直接拼接。先统一不同解释，再发布总数；排除冲突不能丢失或被算成已写。见[判断与报告规则](difference-investigation.md)。

## 交接材料与完成条件

| 阶段 | 交接材料 | 完成条件 |
|---|---|---|
| 文件接收 | 来源身份/哈希、原名、文件库 ID/路径、来源类型/用途、通知/附件、页数、重复和范围决定。 | 所有提供文件已分类，范围内正式附件均已识别。 |
| OCR | 文件 ID、页图及准确页号、每页文字、失败页/重试数、预计名单行范围、文件状态。 | 每页均成功或明确失败；达到此边界立即交纠偏。 |
| 纠偏 | 每条正式行的源文件/页码、原转录、纠正文字、视觉核验结果、导出候选和未定字段。 | 全部正式行已对照来源页检查；不可读/有歧义内容明确保留，不丢正式行。 |
| 身份 | 企业 ID/已确认代码、公布行/页、分开的候选名/码、准确本地/平台/公开查询、网址与时间、条件/分页/总量/完成状态、证据引用。 | 候选发现与确认分开；已解决项身份链闭合，其余待核。 |
| 写入 | 来源身份/哈希、唯一幂等键、准确契约版本及支持载荷、预检响应、提交回执、逐项结果。 | 整批原子提交，或已记录回滚及逐项错误。 |
| 验收 | 来源到结果的数量、全部正式行与来源页、事件字段、身份、页图/OCR、回执及重复候选结果。 | 独立读取者逐维确认；未解决业务错误阻止验收完成。 |

每次交接分别列文件元数据/入库、页图/转图/OCR、事件元数据、企业身份状态。文件已存储不代表页完整；正式行已入库也可仍缺信用代码。

## 重试与恢复

- 只重试失败单元。临时 OCR 故障重试对应页图，保留成功页，不因一页失败重跑全部。
- 实时平台操作遵循[平台查询说明](./platform-query.md)。独立查询通过应用 REST/MCP 单查或批量提交，按稳定 itemId 路由，不用名称/代码或数组顺序代替。检查失败后只重试未完成 itemId/页，保留已完成分段、行与时间。应用在批量、单查、旧入口和退避中全局最多并发两个请求；调查者数量与平台请求额度分别控制。
- 超时、会话过期、HTTP 200 登录页、分页不全属于失败/部分证据，不是零记录。保留准确查询及分页边界。
- 统一导入整批全成或全败。平台、别名和其他独立命令失败后，保留原有证据，修复报错项并按命令契约同键重试。公布原行在 `staged` 后固定。同一来源版本的身份核对可在失败后修正并重新补充，原行有更正时使用新版本和新幂等键。
- 公布留存响应丢失时，用完全相同的载荷和幂等键重取 `intakeId` 和 `sourceDigest`。补充响应丢失时，先读取 `GET /api/roster/import/intake/{id}` 的状态和回执。已补充版本保存原核对决定和回执，重试使用相同决定。
- 提交响应丢失时，先用 `GET /api/roster/import/receipts` / `get_roster_import_receipt` 按原 `idempotencyKey` 或已知 `batchId` 查询；精确历史回执用 `receiptId`，三者只选一个。读取需独立 API/MCP token，不重新提交。区分 preflight、processing、failed、committed；HTTP 成功不等于业务提交成功，processing 保留未完成。按需用 `/receipts/history` / `list_roster_import_receipts` 查历史、`/receipts/items` / `list_roster_import_items` 分页查逐项结果。receiptId 与私有 batchId 不互换。检查已知回执后才决定是否明确同键重试，不自动重提或换新键。
- 必需身份/来源字段无法由当前契约支持时保留待处理并开边界明确的票，不绕过校验、不编造计数、不接受真实业务错误。
- 单一验收维度失败不放弃整轮；保留成功结果，只重试/修复失败单元，再核验受影响维度。非阻塞缺口单列；未解决业务错误仍阻止验收完成。

无凭据单查、批量、会话过期、第二页失败、同代码多关系的流程见[示例](../examples/README.md)。检查真实应用路由与响应，不能只读源码判通过。

## 必须覆盖的交接情形

| 情形 | 处理要求 |
|---|---|
| 多页 PDF 与其他文件同时处理 | 使用共享 OCR 上限，每页均有成功/明确失败后即交该文件；保留成功页并逐行对照来源页。 |
| 同企业出现于多个文件 | 按企业 ID/已确认代码复用调查；每文件保留自己的行/页依据。同名只连接候选。 |
| 公开依据证明旧名，平台返回现名 | 查旧名及变体并取得旧名到代码证据，再按码查询现名。遵循[身份说明](./uscc-recovery.md)的 `cross_source` 条件；缺完整名称查询量或被当前校验拒绝时待核并记 #6。 |
| 当前载荷被拒绝 | 保存预检/提交错误及原子回滚结果，保留已完成产物；修正报错字段后同来源、同键重试。规则不支持时开/更新票，不绕过。 |
| 提交回执丢失 | 用原幂等键及当前回执行为确认已提交或失败后，才开始新批次；不换新键。 |
| 既有事件或出处坐标错误 | 按[既有记录更正边界](./workflow.md)处理；不支持的事件、附件、名单序号更正跟踪 #34，页码专用接口只改已核实 PDF 页码。保留已完成结果等待更正。 |

issue #35 中海尔施、众鑫、华盛、展慈只是演练线索；无独立证据时不写入名称历史、别名或身份决定。
