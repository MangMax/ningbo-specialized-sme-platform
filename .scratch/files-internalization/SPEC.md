# 来源文件内化(File Store)

> 追踪器:本地文件(`.scratch/files-internalization/issues/`)。词汇见 [GLOSSARY.md](../../GLOSSARY.md);文件边界见 [docs/adr](../../docs/adr)。

## 问题陈述

来源文件(经信局公布文件、工信部导出)散在 `20261013/` 顶层目录,**不在任何仓库里**,两个仓库是 `app/` 与 `pipeline/`。因此:

- 台账的 `record_evidence.source_file` 存的是**相对数据根**的路径,解析不到仓库内文件,看板只能显示纯文本,点不开、预览不了;
- 文件不受版本控制,`app`/`pipeline` 换个机器或 clone 出来就拿不到源文件;
- 后续要做导入/导出/上传,却没有一个明确的文件归属与目录规则。

## 解决方案

在 **app 仓库内**建立**来源文件库(File Store)**:`app/files/`,把公布文件与导出**内化**进来,按**来源 / 类别 / 年份 / 批次**分层;`record_evidence` 指向**文件库内相对路径**;app 用 Nitro 路由读取并预览/下载。文件系统属于 app;pipeline 后续往同一目录导入。

**内化范围(用户明确)**
- 经信局:**PDF + `.doc`**(36 个,≈91M)。
- 工信部:**Excel**(3 个,≈23M)。
- **不内化**与 PDF 同名的 `.docx` —— 那是用户手工 OCR 的产物,后续将由「从 PDF 自动提取」替代(本期不做)。

## 目录规则(服务后续导入导出)

`files/<source>/<kind>/<year>/<batch>/<filename>`

- `source`:`jxj`(经信局)/ `miit`(工信部)。
- `kind`:`announcement`(公布文件)/ `export`(导出表)。
- `year` / `batch`:公布文件取「年份-批次」;导出表无批次,省略。
- 例:`files/jxj/announcement/2024/1/甬经信中小〔2024〕72号…名单的通知.pdf`
      `files/miit/export/创新型中小企业导出Excel.xlsx`
- 文件名保留原样(含文号),便于人读与回溯。

## 用户故事

1. 作为经办人,我想在企业详情里**点开出处文件**,以便核对原始名单。
2. 作为经办人,我想看到出处的**可读路径**(来源/年份/批次),以便知道它出自哪份文件。
3. 作为维护者,我想源文件**随仓库一起版本控制**,以便换机器/协作时拿得到。
4. 作为维护者,我想文件按**来源/年份/批次**分层,以便导入时按规则定位、导出时按规则命名。
5. 作为维护者,我想导入管道**按同一规则**解析文件、写入仓库内相对路径,以便看板与文件库一致。
6. 作为维护者,我想以后能接入**上传(tus)**,以便把新文件按同样规则写入文件库。

## 实现决策

- **文件库位置**:`app/files/`(app 仓库内,纳入版本控制)。**不放 `public/`**(build 后只读,无法上传)。
- **路径语义**:`record_evidence.source_file` 改为**相对文件库根**的路径(如 `jxj/announcement/2024/1/…pdf`),由 app 解析为可访问 URL 或本地路径。
- **服务方式**:`server/routes/files/[...path].get.ts` 读 `runtimeConfig.filesDir`(默认 `./files`)回吐;含 content-type 与路径穿越防护。PDF 可内联,`.doc`/`.xlsx` 下载。
- **迁移脚本**:在 pipeline 内加一个「建文件库」脚本(读 `--root` 下的源文件 → 按规则复制/改名到 `files/`),幂等;并让 `parseAnnouncement` 写入的 `sourceFile` 用新规则路径。
- **tus 接入**:本期只**调研验证**(单独票),不改动实现。

## 测试决策

- **文件库脚本**:给定小型 fixture 目录,断言生成的目录结构与文件名符合规则、幂等。
- **路径解析**:app 侧断言 `source_file` → 文件库 URL/路径的解析正确。
- 只测外部行为(生成的路径、可解析性),不测实现细节。

## 范围之外

- 从 PDF 自动提取文本替代手工 OCR(后续)。
- tus 的实际接入(本期仅调研)。
- 比对票 12 仍挂起。

## 补充说明

- 目录名 `20261013` 是任务日期,不是数据年份;文件库里的 `year/batch` 来自**公布文件本身**。
- 内化是一次性迁移;此后文件库随仓库演进。
