# [P0] RL-01 — 固化对比口径与最小名录数据契约

**级别：** scope:XL — 企业、称号、曾用名和差异证据边界属于领域模型决策；先完成数据契约和独立评审，再开始实现。
**难度：** 高｜**主要难点：** 保证正式公布历史、平台快照和企业身份沿革不相互覆盖｜**建议模型：** magpie + DeepSeek（高推理）

## Parent

[总规格 #14：专精特新企业名录规格](https://github.com/MangMax/ningbo-specialized-sme-platform/issues/14)

## What to build

一份可供名录、接口查询和年度快照功能共同使用的短规格：明确企业身份、曾用名记录、称号事件、平台快照、差异原因及后续措施的边界，并用用户给出的多称号、接口多关联及经信局曾用名、迁入和复核案例演示预期结果。

## Acceptance criteria

- [ ] 对比以正式公布文件为准，平台导出只表示采集时点的现状。
- [ ] 一家企业可有多个称号及多个认定/复核事件；去重不删除事件。
- [ ] 明确接口未查、接口失败、接口无记录、已确认原因和待核实的差别。
- [ ] 将企业曾用名定义为关联企业身份的领域记录，能保留名称原值、来源关系和核验状态；来源未给出的有效时间不推测。
- [ ] 写清接口关系如何支持代理核验曾用名、回填统一社会信用代码并保留多关联；不建设模糊推断引擎。
- [ ] 差异原因与后续措施配对记录，已知原因覆盖外迁、注销、更名、未更新和迁入；新原因可凭证据扩展。
- [ ] 证据不足、关系冲突或同名多主体时进入待核实，不自动合并。
- [ ] 用用户提供的 91330211255994457P 多关联别名案例及复核失败后重获批案例核对规格。
- [ ] 本票只产出数据契约与验收样例，不提前迁移生产数据或改页面。
