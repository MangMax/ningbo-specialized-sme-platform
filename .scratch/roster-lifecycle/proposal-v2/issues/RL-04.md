# [P0] RL-04 — 提供跨称号去重企业总表与差异原因

**级别：** scope:L — 跨称号企业总表同时涉及读模型、API、筛选和证据展示；按下面小切片交付。
**难度：** 高｜**主要难点：** 企业去重后仍要准确汇总称号历史、原因、证据和数量口径｜**建议模型：** magpie + DeepSeek（高推理）

## Parent

[总规格 #14：专精特新企业名录规格](https://github.com/MangMax/ningbo-specialized-sme-platform/issues/14)

## What to build

用户在一个企业总表中查看三个称号的去重企业、正式公布历史、当前平台状态和有证据的差异原因；可以筛选公布名单缺失、平台额外出现、迁入及待核实等情况。

## 实施拆分（每项不超过 scope:M）

- [ ] 建立跨称号的一企一行查询结果，同时保留所有称号事件与来源。
- [ ] 展示差异原因、证据和后续措施，并提供相应筛选。
- [ ] 统一并验证总数、筛选和导出的计数口径。

## Acceptance criteria

- [ ] 同一企业在总表只出现一行；展开后可查看所有称号、批次、认定/复核事件和正式来源。
- [ ] 公布文件条目全部保留，包括未匹配平台导出、缺少信用代码和待人工核对记录。
- [ ] 两个方向的差异均能筛选：公布有而平台无、平台有而公布无。
- [ ] 已确认的迁入、迁出、注销和平台未更新原因显示接口证据；不确定状态显示待核实。
- [ ] 企业详情能查看已确认的曾用名及对应来源/核验信息；按现名或曾用名搜索均定位到同一企业。
- [ ] 每项差异展示已确认原因、证据和后续措施；未知原因可作为有证据的扩展原因保留。
- [ ] 能查看迁入企业原称号、年份及批次；别名歧义或多关联不造成错误合并。
- [ ] 页面总数说明统计的是企业数还是企业×称号数，筛选和导出使用一致口径。
