**级别：** scope:L — 年度预览、应用、接口复核与当前状态变更涉及数据库、API、页面及重放；按小切片实施。
**难度：** 高｜**主要难点：** 安全更新当前状态，同时不误删正式历史且支持幂等重放｜**建议模型：** magpie + DeepSeek（高推理）

## Parent

[总规格 #14：专精特新企业名录规格](https://github.com/MangMax/ningbo-specialized-sme-platform/issues/14)

## What to build

年度更新操作者导入最新公布文件和最新三张平台导出表后，可先检查增量，再应用变更；系统更新当前企业状态和解释，同时保留全部正式历史。

## 实施拆分（每项不超过 scope:M）

- [ ] 生成年度导入预览，逐项呈现新增、更新、移除和待核记录。
- [ ] 按正式历史保护规则应用状态更新与允许的移除，并保证重复回放幂等。
- [ ] 刷新接口原因/措施及其证据；查询失败时禁止据此应用删除或原因。

## Acceptance criteria

- [ ] 更新前显示新增、更新、将移出当前总表及待核实数量，并可查看对应记录。
- [ ] 最新公布文件追加正式称号事件，不覆盖以往认定/复核事件。
- [ ] 最新平台表形成新快照，两个接口重新核验新增、消失或状态变化的差异。
- [ ] 仅由历史平台导入出现、从未在任何正式公布文件出现且最新快照也不存在的企业，从当前总表移除。
- [ ] 曾出现在正式公布文件的企业不会因平台缺失而删除；仅更新当前平台状态。
- [ ] 相同年度、相同来源重放幂等；应用结果和失败项可追溯并可重试。
- [ ] 接口失败时不应用基于失败结果推断出的删除或原因。
