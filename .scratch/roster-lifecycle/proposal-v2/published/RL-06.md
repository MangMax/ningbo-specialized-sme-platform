**级别：** scope:M — 只处理接口曾用名核查后仍缺信用代码的剩余条目。
**难度：** 中｜**主要难点：** 同名主体和地区不一致时不能误填或误合并｜**建议模型：** magpie + DeepSeek

## Parent

[总规格 #14：专精特新企业名录规格](https://github.com/MangMax/ningbo-specialized-sme-platform/issues/14)

## What to build

完成 RL-03 的工信部双接口曾用名匹配后，名录维护者能从总表筛出仍缺少统一社会信用代码的企业，并依据公开主体来源逐家补录；无法可靠确认的企业保留空值并进入待核清单。

## Acceptance criteria

- [ ] 只将接口曾用名匹配后仍未解决的企业列为本票网络补查对象，并可追溯其接口匹配结果。
- [ ] 待查清单包含企业名称、地区、称号、来源文件及可用页码。
- [ ] 每个补入代码均保存可复核的公开内容来源、查证日期和主体对应依据。
- [ ] 同名多主体、地区不符、代码格式不合法或证据不足时不填猜测值，转为冲突/待核实。
- [ ] 不覆盖已存在的代码，不因补代码自动合并身份。
- [ ] 已由接口关系确认并建立曾用名记录的企业不重复进入网络补查清单。
- [ ] 补录通过应用统一 API 完成，可重放并输出补齐、冲突、未找到和待核实数量。
