**级别：** scope:L — 来源页码、文件身份、预览定位和名录交互跨 API 与 UI；按小切片交付。
**难度：** 中｜**主要难点：** OCR 页序、PDF 实际页码和预览定位必须指向同一来源内容｜**建议模型：** magpie + DeepSeek

## Parent

[总规格 #14：专精特新企业名录规格](https://github.com/MangMax/ningbo-specialized-sme-platform/issues/14)

## What to build

用户从企业或称号事件上的来源页码打开原始文件预览，并定位到对应 PDF 实际页面；返回时仍保留当前名录上下文。

## 实施拆分（每项不超过 scope:M）

- [ ] 保存能标识来源文件和 PDF 实际页码的证据字段。
- [ ] 从名录记录打开对应来源预览并跳转到实际页。
- [ ] 覆盖无可靠页码格式、附件边界和返回后保留名录上下文。

## Acceptance criteria

- [ ] 名录行显示来源文件及可用的实际页码；没有可靠页码时明确留空。
- [ ] 点击来源能打开对应原文件预览并定位到该 PDF 页。
- [ ] 附件切换和跨页名单的页码与 PDF 实际页序一致，不把 OCR 序号误当 PDF 页码。
- [ ] Word、Excel 等没有可靠分页的文件不跳转到猜测页。
- [ ] 返回后保留原筛选与查看位置；重命名文件后仍能解析到同一来源内容。
