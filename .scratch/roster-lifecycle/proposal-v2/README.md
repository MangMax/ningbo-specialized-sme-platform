## 提案采用的产品顺序

先确定最小数据口径，并行完成小巨人历史导入、平台接口解释和导出快照；核心交付是跨称号去重、可查看证据和差异原因的企业总表。随后优先完成用户名单功能和通用清理管线 API；缺代码补查与年更依赖该 API。文件命名作为低优先级单独决策。

## 测试接缝提案

主接缝沿用当前 `/api/comparison` 的真实响应并由 `/comparison` 页面消费：用 SQLite 测试数据覆盖公布源、三张平台快照、同一企业多称号、平台当前名与经信局曾用名不同、一个信用代码多条关系、迁出/注销/更名/未更新/迁入及其他原因、歧义候选与待核实状态，验证身份和曾用名回填、按现名或曾用名搜索、各原因对应的后续措施及证据展示一致。导入功能沿用真实 HTTP API 契约做端到端写入与重放验收；来源页跳转沿用现有文件读取和预览能力验证定位。避免新增仅为测试而建的内部抽象。

票面已按批准范围整理；发布后按现有核心/后续优先级保持未分派。
