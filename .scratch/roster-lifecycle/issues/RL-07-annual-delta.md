# RL-07 — 年度增量更新与平台迁出删除

- **级别**：`scope:L`（导入、差异计算、生命周期更新和审计）
- **优先级**：P1
- **难度**：高｜**主要难点**：区分平台独有企业删除与正式历史记录保留，并确保重复年度回放幂等｜**建议模型**：magpie + DeepSeek（高推理）
- **状态**：ready
- **阻塞项**：RL-04、RL-05、RL-11

**为什么现在做**：以后每年只有最新公告和导出表，必须能安全增量维护。**风险**：错误删除正式企业或重复重放造成错账；应用前需展示差异预览和计数。

## 目标

以后每年只导入最新公布文件和最新三张导出表，通过差异完成新增、更新、删除和原因刷新。

## 更新规则

- 新公布文件为本年度正式称号事件来源；已有企业则追加事件，不覆盖历史。
- 新的三张平台表形成当前对照快照；两接口重查新增、消失或状态变化的企业，刷新原因和证据时间。
- 仅因过去平台导出出现、从未出现在任何公布名单而进入当前总表的企业，若最新平台导出中也不存在，应从当前企业总表移除。
- 有正式公布历史的企业保留在历史名单中；平台消失只更新当前状态，不删称号事件。

## 验收

- 同一年度输入重复运行幂等；可预览本次新增/更新/移除/待核实数量后再应用。
- 用例覆盖：仅平台迁入后又迁出、正式获批企业平台缺失、外地迁入有别称号批次、公司注销、平台接口失败。
- 正式历史记录不会因平台导出缺失而消失；平台独有企业满足删除规则时从当前企业名单移除。
- 记录本次输入文件版本、差异摘要和写入结果；失败可从源批次重放。

## 实施切片（每项 ≤M）

- 只读计算新增/更新/移除/待核实的年度差异预览。
- 通过 API 幂等应用变更并保留输入快照身份。
- 刷新总表原因状态并核对平台独有企业移除条件。
