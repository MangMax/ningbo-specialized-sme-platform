# RL-06 — 本批缺信用代码企业联网补查

- **级别**：`scope:M`（逐项查证和单一写回流程）
- **优先级**：P1
- **难度**：中｜**主要难点**：同名主体和地区不一致时必须保留空值而不是误填｜**建议模型**：magpie + DeepSeek
- **状态**：ready
- **阻塞项**：RL-11 的企业/别名/信用代码写入 API

**为什么现在做**：缺少信用代码会削弱跨表比对，需补齐本批仍缺失项。**风险**：网络搜索容易把同名外地企业误认成宁波主体；逐家保存内容页出处和地区核验。

## 目标

对当前总表里缺统一社会信用代码的企业做逐家公开网络查证，补齐可靠结果并保留出处。

## 验收

- 先从当前正式名单产生带企业名、地区、称号和来源页码的待查清单。
- 每个已补代码附公开信息来源 URL、查证日期、名称/地区对应依据；同名多主体、跨区不符或证据不足留空并标待人工。
- 只补缺失值，不覆盖已有代码、不做身份合并；信用代码校验失败或已被其他企业占用时拒绝写入。
- 结果通过 app API 写回并可按来源重放；输出“补齐 / 冲突 / 未找到 / 待人工”分项和闭合数量。
- 不把搜索引擎摘要本身当成主体证据，也不猜代码。
