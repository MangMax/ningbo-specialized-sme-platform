# RL-04 — 跨称号去重企业总表及差异原因

- **级别**：`scope:L`（数据读模型、API 和用户视图）
- **优先级**：P0
- **难度**：高｜**主要难点**：企业去重不能折叠称号/批次历史，差异原因又是时态证据｜**建议模型**：magpie + DeepSeek（高推理）
- **状态**：ready
- **阻塞项**：RL-01、RL-03

**为什么现在做**：用户要按企业使用总表，并在同一处看三个称号及差异原因。**风险**：只保留当前标题或单条平台记录会丢掉迁入来源与历史事件。

## 目标

交付一份跨三个称号去重的企业总表，同时保留企业的全部称号、认定/复核事件和平台差异，不再把三个称号拆成互不相干的最终名单。

## 范围

- 一家企业在总表中只出现一次；称号作为多值关系/事件展示。
- 按公布名单列出权威称号事件；按平台快照列出当前平台存在情况；将平台原因作为带时间和来源的解释记录。
- 支持“平台多出、公布名单缺少”“公布名单有、平台缺少”、外地迁入、外迁、注销、平台信息未更新、未解释等状态。
- 迁入企业如能从申报记录核实原地称号，展示原称号、年份和批次；未核实则显示待补证。
- 未匹配导出表的正式名单企业仍然入库并进入清理/人工差异视图。

## 验收

- 三称号合并查看时同一企业仅一行，展开能看到三称号分别的历史事件和文件出处。
- 指定平台多关联/别名记录只归属可证实的企业，无法判定时不合并。
- 解释状态旁可打开平台查询证据和源名单证据；未查、失败、无记录、确定原因是不同状态。
- 统计按企业或称号计数时明确单位，不把多称号企业重复算成多家企业。

## 实施切片（每项 ≤M）

- 建立企业去重读模型并保留称号事件关系。
- 提供差异、解释和原称号批次的 API 查询契约。
- 实现统一企业总表、原因筛选与事件/证据展开视图。
