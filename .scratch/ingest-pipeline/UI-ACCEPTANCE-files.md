# `/files` 文件管理页 · UI 验收记录

范围:票 09(文件管理页)+ 票 17(文件含多段)的**呈现层**。
基准:`.scratch/ui-redesign/DESIGN.md`,以及同门已打磨合格的三页(台账 `pages/index.vue`、统计、数据质量、比对)。
方法:自建 worktree(`/tmp/oilui2-wt/app`,`feat/files-ui-accept`)、真 `pnpm install`、`pnpm dev --port 3478`,用 `oil-ui` 的 `scripts/shoot.mjs` 取**真实截图**(亮色 / 暗色 / 390px 窄屏 / 表头吸顶 / 各状态),逐条对照后改,再重截同一批图复评。

> 截图在 `evidence/before/`(改前)与 `evidence/after/`(改后),`gitignore` 已覆盖,不入库。
> 亮/暗两套通过给 Chrome 传 `--blink-settings=preferredColorScheme=1|0` 取得(本机 macOS 全局为暗色,不这样做两种模式会拍成同一张)。

## 一、结论:改前为什么"不合格"

用户判它不合格,最刺眼的是**这一页不像同一个产品里的另一页**。具体是四件事:

1. **表格比同门宽 1.4 倍,把最主要的操作推出了屏幕。** 表宽 `min-w-[1240px]`,1440 视口下真实表格宽 1240px > 容器 1124px —— 于是**每一行都在横向滚动**,最右边的「编辑 / 预览 / 移出」默认看不见。台账页 `min-w-[1100px]` 在 1440 下正好放得下,只有窄屏才滚。文件页 12 列不是问题,列宽没按内容量过才是问题。
2. **文件名列下面压着一行 `rel_path`,而它对每一行都截在同一个位置。** `jxj/announcement/2026/1/甬经信中小〔20…` —— 20 份经信局文件全是这一串,既分不出谁是谁,又把行高从 44px 撑到 52px,同屏少两行。这是"看着密、其实没信息"的典型。
3. **来源写成了灰底 Badge,把来源语义丢了。** 台账页用 `SourceChip`:经信局 = 藏青方标、工信部 = **金色**方标(DESIGN.md:「金 = 国家级」)。文件页自己写了个 `variant="quiet"` 的灰 Badge,工信部那 3 份导出表和经信局的 20 份公布文件长得一模一样。**同一个产品里同一个概念两套画法。**
4. **`+N` 没有单位,读不出是什么。** 票 17 给「内容年份/批次」加了 `seriesLabel` 上限(`2021、2022 +4`)。列头写的是「年份」,右边「批次」列也出现一个 `1、2 +2` —— 两个裸 `+N` 并排,不悬停就不知道「+4」是 4 年还是 4 段还是 4 批。用户说的「加了 `+N` 上限后反而看不懂」就是这里。

另外三处较小的:

5. **两个 `年份` / `批次` 列头分不出「公布」和「内容」。** 左列叫「公布年份/批次」,右列就叫「年份」「批次」—— 少了「内容」这个限定词,一列有前缀一列没有,读起来像是同一个东西的两种写法。
6. **段明细没有归属感。** 展开后是一个灰底 `<Table>` 平铺,没有缩进也没有连线,和上面那一行的关系只靠背景色暗示。
7. **深色下删除弹窗的红字不达标。** 实测 4.25:1(阈值 4.5:1)。根因是共享的 `alertVariants.destructive` 给说明文字加了 `text-destructive/90`。

## 五、删掉的文字

- 文件名列下的 `rel_path` 次行(信息量为零:20 份文件截在同一个位置)——路径保留在文件名的 `title` 与编辑弹窗的只读块里。
- 段明细下的「共 N 段。年份是段的内容年份(复核段为被复核的原认定年份);「公布年份/批次」与段无关,是这份文件在目录上的公布批次。」→ **只留「共 N 段」**。列头已经分别写着「公布年份/批次」和「内容年份」,不必再讲一遍数据模型。
- 编辑弹窗:「不是「未知的某年」」「导出表、年份区间不落这一段。」「只改分类元数据;库内路径与磁盘上的文件都不动。」(后者与标题下的说明重复)。
- 上传按钮的 tooltip 文案(制作说明,不入界面)。
- 页头描述:「文件库里的全部来源文件。年份/批次列是文件内容里的段,一份文件可含多段。」→「文件库里的全部来源文件;展开任意一行看它含哪些段。」(前一句在解释列语义,列头已经写清楚了)。

## 六、一处对比度修复(为什么动了共享变体之外的写法)

深色下删除弹窗的引用数提示实测 **4.25:1**,低于 4.5:1。根因在共享的 `components/ui/alert/index.ts`:

```
destructive: "text-destructive bg-card [&>svg]:text-current *:data-[slot=alert-description]:text-destructive/90"
```

`*:data-[slot=alert-description]:text-destructive/90` 给说明文字加了 90% 透明 —— 而 DESIGN.md 里那笔「深色下 5.3:1」的账算的是**全不透明**的 `--destructive`。那条规则与 `.text-destructive` 同权重、位置更靠后,所以只有 `!important` 压得过。

在 `components/files/*` 里用 `text-destructive!` 覆盖,**没有**直接删共享变体里的 `/90`:它同时被 `pages/comparison.vue` 与 `pages/enterprises/[id].vue` 用着,改它超出本票的改动面。若后续要一并修,改 `alert/index.ts` 一处即可。
