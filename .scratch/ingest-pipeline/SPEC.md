# 入库管线重整 — 规格

> 追踪器:`.scratch/ingest-pipeline/issues/`。词汇见 [GLOSSARY.md](../../GLOSSARY.md)。
> 承接:[data-integrity](../data-integrity/SPEC.md)(身份归并安全阀与重建)、[files-internalization](../files-internalization/SPEC.md)(文件库)、[comparison](../comparison/SPEC.md)(两侧比对)。

## 问题陈述

现在入库靠**命令行人肉操作**:源文件散在数据根、pipeline 用 `--root` 指过去解析。这有三个后果:

1. 新文件进来只能靠「丢进目录 + 跑命令」,没有界面;
2. 解析源是**人工 OCR 出来的 `.docx`**,已实测会错(丢整段、序号打错),而权威件是**扫描 PDF**(无文字层,机器读不出);
3. 出处只到「文件/附件/序号」,**没有页码**;企业身份靠两个来源互证,**缺统代时没有外部查询手段**。

## 目标(用户 2026-10-14 原话归纳)

1. **新增「文件管理」页**:统一管理**现有 23 个 + 之后上传的**全部文件。
2. **上传时手动设置来源 / 年份 / 批次**,也允许**后续由代理识别回写**。
3. **代理只从「已上传的文件」解析入库** —— 不再扫数据根目录。
4. **新增 OCR 通路**(三条都用,**不本地部署**):
   - 用户在页面**点一下**调 PaddleOCR **API** 识别(异步、可批量,优先);
   - 用户把**已在官网识别好的结果**上传(结果直接入库);
   - 代理经 **MCP** 取图解析并写回。
   - 结果**带页码**,导出 **markdown** 便于处理。⇒ 见 [ADR-OCR-通路](../../docs/adr/)。
5. **解析结果入库**:新建库存放解析结果,**关联到图片**;若文件**没设分类**,由程序或代理**回写**。
6. **缺统代 → 代理联网查询**补齐。
7. **对照工信部平台**(两个接口,已实测可用):
   - `businessList`(rdjb:1 创新型 / 2 专精特新 / 3 小巨人)→ 解释「为什么在平台内、不在公布文件内」;
   - `applyList` → 申报记录(字段多)。
   - 口径:**以公布文件为准**,对照导出文件;**不在公布文件的需补**(可能是外地企业),**不在导出文件的**(可能注销/外迁)。

## 已实测的技术前提

| # | 前提 | 结果 |
|---|---|---|
| 1 | 工信部 `businessList` 接口(**带着用户给的 cookie**) | ✅ **200,返回 HTML 表格**(不是 JSON) —— 是旧式 `dwz` 框架的 `businessListGrid`。**解析要按 HTML 表格抓,不能当 JSON。** cookie 是会话级的,会过期 ⇒ 要能配。 |
| 2 | tus 上传端点 | ✅ 已在 app(`server/utils/tus.ts` + `middleware/tus.ts`),落位规则 `landingSegments` 是**纯函数**、可测。 |
| 3 | PaddleOCR | 用户给了 **access token** 与 **MCP 配置**(`uvx --from paddleocr-mcp`);**不本地部署**,走 API/MCP。 |
| 4 | 页码 | ✅ **可推**:docx 节序 = PDF 页(见 [data-integrity/SPEC](../data-integrity/SPEC.md));OCR 结果自带页码,更好。 |

> ⚠️ **不要把 token 写进仓库** —— 用 `NUXT_*` 环境变量 / 页面配置(见票 09),仓库里只留 `.env.example` 占位。


## 更正:文件的「年份 / 批次 / 事件」是**多个**(2026-10-14,用户指出)

一份公布文件**常常含多年份、多事件** —— 实测 19 份经信局文件里 **7 份是多段**:

| 文件 | 实际含的段(称号一律由来源定) |
|---|---|
| 省专 2022(145号) | **认定 2021**(301 行)+ **认定 2022**(413 行)—— 两年 |
| 省专 2024 第二批(192号) | **认定 2024/2**(389,附件1)+ **复核 2021/2**(67,附件2) |
| 省专 2025 第二批(30号) | 认定 2025/2(423)+ 复核 2025(260) |
| 创新型 2025 第二批(165号) | 认定 2025/2(427)+ 复核 2025(394) |
| 创新型 2026 第一批(65号) | 认定 2026/1(382)+ 复核 2023/1(75) |

**3 份工信部导出也全是多段**(`maintain`,跨 2021–2026 多个维护批次)。

⇒ **文件级的单个 `year` / `batch` 是错的**。真实粒度是**「段」**:`(称号, 事件类型, 年份, 批次, 附件)`。
**票 09 已按单值建表并合入 —— 由票 17 更正**;票 11 的输入契约随之改为「按段」。

> 附件名写法不一(实测有「附件」「附 件 1」「附件1」「附件2」),**要归一**。

## 分期(**我定的节奏** —— 每期都有独立可验收的产出)

| 期 | 主题 | 票 | 验收产出 |
|---|---|---|---|
| **一期** | 数据侧:文件管理 + 只吃上传文件 + 分类回写 | 09 → 12 → 10 → 11 | **新文件全程走界面、不再碰命令行**,库里出现新记录 |
| **二期** | 识别侧:OCR 三通路 + 解析结果入库 | 13 → 14 | **一份扫描 PDF 经 API 识别后按页码入库** |
| **三期** | 身份与对照:联网补统代 + 平台两个接口 | 15 · 16 | **缺统代补上;差异可解释(外地/注销/外迁)** |

## 给实现者的硬约束

- **UI 一律 shadcn-vue 官方组件**;不得手写或原生 `<table>/<input>/<select>`。沿用现有设计 token 与 `DESIGN.md`。
- **凭证不入库**:token / cookie 走页面配置或环境变量,仓库只留占位。
- **身份判定仍守 [data-integrity/SPEC](../data-integrity/SPEC.md) 的安全阀**:单一来源不得触发归并;拿不准 → 空值 + 标记。
- **空值优于错误值**:联网查到才写;查不到保持 `uscc_missing` + 待确认。
- 提交前 app `pnpm typecheck && pnpm test`、pipeline `vp check && vp test` 全绿。
- **同仓一次只跑一个会话**(共用工作目录会互相踩),分支从干净 `main` 起。

## 范围之外

- 不做本地部署 OCR。
- 不改比对口径(三期只是给差异**加解释**,不改判据)。
