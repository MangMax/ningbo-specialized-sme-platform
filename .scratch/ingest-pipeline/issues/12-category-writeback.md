# 12 — 分类回写：代理读取文件后补齐分类

**What to build:** 文件上传时若来源、类别、年份或批次尚未设置（`category_state='unset'`），由清理代理读取用户指定的文件内容，判断其公布来源、文件类型、正文明确写出的年份/批次及称号，再通过文件域写入接口回填 `stored_file`。程序负责字段校验和持久化，不实现分类推断规则。

**Blocked by:** 10, 11

**Status:** done（2026-10-15）。代理正文判断、既有 API/MCP 回填及独立双入口清理入库流程已验收。

## 范围

1. **代理做业务判断。**依据用户指定文件的实际内容：PDF 先转增强 PNG 并 OCR，先匹配三张导出表，再核验未匹配、歧义或冲突行所在页图；DOC/DOCX 和 XLSX 直接读取文字与表格。年份、批次以正文明确列出的名单信息为准，不从文件名、目录名、发布文号或正则规则推算。判断文件是否属于公布名单时也要看正文是否实际列出企业名单。
2. **程序只校验和写入。**使用现有 `set_file_category` 文件域接口回填 `source`、`kind`、`year`、`batch`、`titleCode`。接口校验允许值并返回持久化后的文件行，供代理读回核对。
3. **证据不足时保留未定。**正文缺项、相互矛盾或无法确认文件范围时，不猜、不写入不确定字段；保留 `unset` 并列明需确认的字段和原文依据。

本票不实现按文件名/正文规则自动分类，不新增 `inferred` 状态的程序判定、推断依据存储、批量采纳推断或分类专用 UI。代理可在清理报告中记录来源句、正文年份/批次和判断依据；不要为这类人工判断另建推断引擎。

## 测试

- [x] 文件域接口接受合法分类字段并持久化；返回值可读回核对。
- [x] 未提供的字段保持原值，显式 `null` 清空对应字段；无效字段被拒绝。
- [x] 分类字段补齐后状态从 `unset` 变为 `set`；未补齐或清空后按现有规则保持/退回 `unset`。
- [x] 不为年份、批次或名单范围添加自动推断测试；这些判断由清理代理根据文件正文完成。

## 验收

- [x] 分类回填的年份、批次与正文明确内容一致；不得从文件名、目录或文号推算。
- [x] 通过文件域接口写回后读取文件行核对；证据不足的字段保持未定，并在待确认报告中引用具体文件和正文位置。
