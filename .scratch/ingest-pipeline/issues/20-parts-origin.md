# 20 — 「段」的两条写入路径会互相覆盖(段加 origin,回填只重建派生段)

**What to build:** 给 `stored_file_part` 加**来源标记**,让「票 11 的整体回填」与「代理写回(票 18/12)」**不再互相覆盖**。

**Blocked by:** 11、17、18(都已合入)

**Status:** ready —— **由票 18 的复核发现,不处理会静默丢数据**

## 问题(票 18 交付时点出的「最该先处理」)

段现在有**两条写入路径**,而且没有唯一约束:

| 路径 | 谁写 | 行为 |
|---|---|---|
| 派生 | 票 11/17 的 `backfillFileParts` | **整体重建**:遍历全部 `stored_file` 行,**先删后插**(以 `record_evidence` 为准) |
| 代理 | 票 18 的 `save_parse_result` | 代理把解析出来的段写进去 |

⇒ **代理先写、回填后跑 → 代理写的那几段被整体删掉。** 静默,不报错。

## 要做的

1. **加 `origin` 列**(`derived` / `agent`),或等价机制 —— **注明谁写的**。
2. **回填只重建 `origin='derived'` 的行**;`origin='agent'` 的**不动**。
   - 同一段两边都写时,**谁优先**要写死并测(建议:代理写的优先,因为它是"有人看过"的结果;但**同一段两边冲突要能被发现**,不是静默取一个)。
3. **加唯一约束**:`(file_id, title_code, event_kind, year, batch, attachment)` —— 防重复段(现在没有)。
4. **测试**:
   - [ ] 代理先写一段 → 跑回填 → **该段还在**;
   - [ ] 回填**幂等**(跑两次不增不减);
   - [ ] 同一段两边都写 → 按写死的规则收敛,且**能查出冲突**。

## 验收
- [ ] 「代理写 → 回填」这条顺序**不再丢数据**(实测);
- [ ] 迁移一个新编号(**排在当前最后之后**);
- [ ] app `pnpm typecheck && pnpm test` 全绿。
