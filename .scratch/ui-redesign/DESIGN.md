# UI 重设计 · 设计说明

任务：把只读看板从「shadcn 原始状态」改成一套高效、流畅、不花哨的后台界面。
范围：视觉 token → 共享组件 → 四个页面。约束：一律在 shadcn-vue **官方组件**基础上改，不写原生 `<table>/<input>/<select>`。

## 一句话北极星

**一眼读出梯度与出处** —— 台账的每一条记录都同时带着「称号等级」和「来源」，扫一眼就要分得清谁是小巨人、谁是创新型，谁是市级认定、谁是国家级名单。藏青为骨，层级靠秩序不靠装饰。

## 它是什么

宁波市经信局内部查阅用的**只读台账看板**。使用者是业务处室的人，一天要翻很多页、反复查同一家企业。
所以：**密度优先于留白，秩序优先于趣味，动作优先于装饰。**

## 三个判断

1. **认品类**：数据密集的政务台账。标杆是各级政务数据平台和内部 MIS —— 好的那些都靠**列语义色阶 + 稳定的表格节奏**，不靠卡片和渐变。
2. **首屏看什么**：一屏 20+ 行记录，用户要快速回答「这家什么等级、谁认定的、哪一年、还能不能点进去」。
3. **品牌从项目里出**：本仓库自带 `政企汇报风格包`（政务藏青蓝 `#14417E` + 金色方形标记 `#C29A3B` + 点睛红 `#B01F24`）。app 原先完全没用上，纯灰阶——这正是「过于单调、缺少活力」的根因。**沿用这套既有品牌资产**，不另造色板。

## 关键语义

| 概念 | 视觉规则 | 理由 |
| --- | --- | --- |
| 称号梯度 | 实心藏青（小巨人）→ 藏青浅底（专精特新中小企业）→ 中性灰（创新型） | 等级由高到低是一条色阶，不是一个标签 |
| 国家级 | 金色 6px 方形标记 | 风格包里「金 = 国家级/点睛」，只做图形标记，不写金色文字（白底对比度仅 2.6:1） |
| 来源 | 经信局=藏青方标（市级）；工信部=金色方标（国家级） | 与称号标记同一套语言：金 = 国家级 |
| 事件 | **深一档实线**（认定）→ 普通描边（复核 / 维护）→ 虚线（入库培育） | 用**线型与线重**表达「是不是已成立的称号」；颜色已被称号梯度占用，事件不再配色 |
| 表格 | 列宽固定、数字等宽、表头吸顶、默认按**称号等级**排序 | 扫视和比较 |

## 改哪些、为什么

- **token 层**：把中性灰阶换成政务藏青体系；圆角 10px → 6px；徽章由 `rounded-full` 改为 4px 方标（全圆角是消费级 App 的语言，政务台账用方标更贴）。表面层级靠**色相偏移**区分（页面底带蓝 `#EFF3F9`，卡片纯白），不只靠明暗。
- **组件使用不当**（用户点名）：
  - `MultiSelectFilter` 用 `Button` 堆成列表 → 换成官方 `DropdownMenuCheckboxItem`（菜单语义、键盘导航、勾选态由组件负责，`@select.prevent` 保持展开）。
  - 统计页拿 `Badge` 当下钻链接 → 换成有明确可点性的 `DrillChip`。
  - 详情页 `Card` 里套 `Card` 里套 `Table` → 拆掉内层面板，同一称号的两个来源**并排两列**用一条竖线分隔。
  - 表格空态用一句灰字 → 用官方 `Empty`；加载态用 `Skeleton`。
- **新增共享组件**：`PageHeader` / `TitleBadge` / `SourceChip` / `EventChip` / `StatTile` / `DrillChip` / `BarRow` / `FilterChip`。
- **查询层**：`listRecords` 的默认排序从 `max(record.id)` 倒序改为**按称号等级**（`TITLE_ORDER` 的 rank）再按企业名。库是整体重建的，`record.id` 只反映导入次序、对使用者没有含义；原先默认首屏 25 行全是「创新型中小企业」，梯度这个主序在落地第一屏完全看不见。
- **四个页面**：台账 / 统计 / 数据质量 / 企业详情，外加布局头。

## 动效（三处基本）

手感取「咔嗒」（磁铁吸合）：短促、到位、不弹，150–200ms。政务工具不该有漂浮感。
1. **主操作反馈**：按钮按下 `active:scale-[0.97]`（改在 `buttonVariants` 里，全站一致）、整行可点导航、筛选 chip 移除。
2. **状态切换来路**：筛选 chip 增删（`TransitionGroup` 150ms 缩放淡入淡出）、出处展开（箭头旋转 + 内容展开）、下钻 chip 悬停。
3. **首次进入出场**：卡片按阅读顺序 35ms 递增淡入上浮，只播一次；`prefers-reduced-motion` 时直接到位。

## 评审与修正

一轮独立评审（存量界面润色，不打分，评审者只看画面不看源码）。采纳的修正：

1. **默认排序看不见梯度** → 改 `listRecords` 默认排序为按称号等级（见上）。
2. **事件线型塌成两档**（认定 / 复核 / 维护 都是同样的 1px 实线）→ 新增 `solid` 变体，认定用 `border-foreground/35`，与复核 / 维护的 `border-border` 拉开。
3. **详情页仍是卡片套卡片**、来源信息写两遍 → 去掉内层面板边框，删掉与方标重复的「来源:…」文字行。
4. **密度不足**（行高 52px）→ 收到 44px，同屏多出 2 行。
5. **深色下红字对比度不达标**（实测 3.67:1，交接里我最初算错了口径 —— 量的是白字对红底，不是红字对深底）→ 深色 `--destructive` 提亮到 `#DE6B70`，对深卡 5.3:1。
6. **侧栏「导航」眉标**（模型默认做法）→ 删。
7. **重复的填缝小字** → 删（详见下）。

不采纳：评审建议把默认排序改成「同屏混排各档」以显梯度 —— 与按等级排序同效，且后者是这套台账自己的主序，更可预期。

## 删掉的文字

- 侧栏分组标签「导航」（三个链接本身就是导航）
- 统计副标题「所有数字都按记录计数」→「按记录计数」（去冗词）
- 数据质量副标题后半「只列出来供人工复核,不影响看板的记录口径。」
- 数据质量每段重复的「完整清单见导入报告。」
- 详情页每段重复的「来源:经信局 / 工信部 · 同一称号的两侧来源各成一条记录」
- 详情页顶部与来源方标重复的「来源:工信部」文字行
- 表格 hover card 里重复企业名与称号的那行

## 未做 / 假设

- **假设**：品牌色沿用仓库里的 `政企汇报风格包`。若用户想要另一套，只需改 `assets/css/tailwind.css` 里的十余个 token，结构不动。
- 不改数据流、接口口径；不动 `db/`、`server/`、`pipeline/`。（唯一例外是上面第 1 条的排序，属页面可见行为。）
- 不加需要新依赖的图表库；统计页沿用已装的 `nuxt-charts`。
- 本机没装 ffmpeg，动效只留了三帧静止图，没有录屏。
