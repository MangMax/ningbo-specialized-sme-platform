# 02 — 名称归一化对齐(公布文件 ↔ 工信部)

**What to build:** 消除「**宁波**X」与「X」这类**已证实等价**的写法差异,使同一企业在两个来源里归到**同一主体**,而不是先被拆成两条、再被错统代误导回填。

**Blocked by:** —

**Status:** done

## 问题(已证实)

- 公布文件写「**贝兹德智能科技有限公司**」,工信部写「**宁波**贝兹德智能科技有限公司」。
- 归一化后是两个名字 ⇒ 建了两个主体 ⇒ jxj 那条「不在工信部名单里」⇒ 触发了本不该触发的回填 ⇒ 拿到错统代 ⇒ 被并入东方日升(见 SPEC)。

> 这是**通用**问题,不是个案:公布文件里大量企业省略了「宁波」前缀。

## 要做的

1. **先量化**:统计两个来源里「**宁波**X」↔「X」成对出现的数量(如 SPEC 里那种),确认这是普遍模式而非偶发。
2. **定规则**:在 `app/lib/domain.ts` 的 `normalizeName`(名称归一化的唯一实现,看板搜索与 pipeline **共用**)里,把**已证实**的等价写法归一 —— 至少:
   - 前缀「宁波」的省略(需谨慎:要有证据证明是同名同实,不能把「宁波X」和「外市X」混为一谈);
   - 全/半角括号、空格(现有规则已部分覆盖)。
3. **不得臆造**:只在**能证明等价**(如同时具备相同/相容的统代、或同一文件同一序号)时才归一;否则保持原样 + 标记。
4. **连带回归**:改 `normalizeName` 会**同时影响看板按名搜索**与 pipeline 归并 —— 两边测试都要跑。

## 注意(反例)

- 不是所有「宁波X / X」都是同一家:`宁波华热机械制造有限公司` vs `宁波华表机械制造有限公司` 是**两家**(各有不同统代)。
- 「宁波」前缀的省略与「**去掉**宁波后与外市企业同名」是两回事,别把外市同名企业并进来。

## 测试

- [x] fixture:「宁波X」与「X」+ **不同统代** → **不**归一。
- [x] fixture:「宁波X」与「外市X」(统代属地不同) → **不**归一。
- [x] app 侧搜索测试仍绿(改的是共享函数)。
