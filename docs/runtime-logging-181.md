# Runtime diagnostics (#181)

The official `evlog/nuxt` module emits one request completion. `evlog.config.ts` sends events to the application allowlist and bounded SQLite drain. It does not replace business audit, import receipts or task results. No business migration is introduced.

Use `appLog(input, context?)` from `lib/logging` for explicit lifecycle events. Dedicated worker entry points call `initializeWorkerLogging()` once, pass request/task context explicitly, and call `closeApplicationLogging()` on graceful exit. Nuxt initializes evlog itself; do not initialize it again in main-process handlers. Error messages/stacks and arbitrary objects are discarded; static application error codes and known identifiers are supported. Never put untrusted text or credentials into operation names, codes or IDs.

All REST `/api/logs` routes and the five `*_runtime_log*` MCP tools require their existing independent API/MCP tokens, including reads. Page access is a separate explicit deployment capability: `NUXT_BROWSER_LOGS_ENABLED=true`, a configured API token, `X-Log-Browser: 1`, and same-origin request provenance. It does not establish user identity and exposes no token to the browser. Default is closed. Client transport and stream endpoints are disabled; browser ingestion and UI are later tickets.

List filters: `from/to`, `level/source/operation/outcome`, `requestId/traceId/taskId/fileId/batchId/resourceId`. `limit` defaults to50, maximum100. Follow `nextCursor` for stable descending sequence pages. New appended events do not shift later pages. No raw-text search or full-error hydration in lists. Detail is by server-generated UUID. GET policy reports actual persisted policy, physical file accounting and failure/drop counters. PATCH policy requires complete `{retentionDays,maxBytes}`. POST clear requires `{from,to,confirm:true}` and optional exact filters; it removes at most1000 events and returns `hasMore`. Repeat the same explicit range to continue. Policy/clear results emit separate diagnostics.

## Storage and budgets

Default independent directory: `<cwd>/.runtime-logs`, configurable with `NUXT_LOG_DIR`. Docker/Compose uses its own `/logs` named volume, separate from `/state`; prepare directory ownership for the runtime node user. No deployment is performed by this change. Existing foreign `events.db` files are refused before schema or journal changes, including symlinks to business databases. Existing logging files carry SQLite application ID1163283527.

Initial defaults:7days and536870912bytes (512MiB), configurable with `NUXT_LOG_RETENTION_DAYS`/`NUXT_LOG_MAX_BYTES`. Persisted policy wins on restart and is reloaded by every worker operation. Capacity accounting sums events.db and journal/WAL/SHM file lengths, excluding filesystem allocation overhead, container stdout and process memory. Main SQLite occupies at most one third of the budget; remaining capacity reserves rollback journal space. DELETE journaling, synchronous FULL, auto-vacuum FULL. Retention and capacity both apply; whichever expires an event first wins. A maintenance pass runs every minute and on writes/queries. Each age/clear batch is limited to1000; capacity pruning is bounded to32 batches per operation. Very large pre-existing over-budget stores may require subsequent passes; operations have a2s deadline and report failures rather than blocking business.

Per process:1024queued events /4MiB;8192bytes per event;64events /256KiB per batch;100ms flush cadence;2s worker deadline;3s total graceful close;32outstanding storage operations. Queue overflow drops newest; no event severity is sampled. Error/failure logs can still be lost to hard failure or saturation. A dedicated thread contains SQLite work. A timed-out worker is terminated and restarted lazily; an acknowledgement lost after commit can leave persistence uncertain. Process counters label such events as dropped/unacknowledged, not proof of absence.

Protected503 replies include safe process status even when SQLite is unavailable. `accepted/stored/dropped/overflow/oversized/drainFailures/fallbackSkipped` counters reset on process restart (`since`); persistent `pruned/cleared` counts survive. Each worker has its own queue and process counters; the main query does not aggregate remote-worker counters. Safe container fallback is limited to10events/second and maxEventBytes+1 per line; fixed stderr fault summaries to1/second and512bytes per line. Both stop writing after backpressure until drain, without a private queue. Skipped stdout events increment fallbackSkipped. Close removes drain listeners immediately; pending-write fault listeners remain only until callbacks settle or the stream terminates, so a late EPIPE stays nonfatal. There is no second full file sink. SIGKILL can lose queued events and in-memory counters; no zero-loss guarantee.

## Verification

Run `pnpm exec nuxt prepare`, `pnpm test tests/logging-foundation.test.ts tests/logging-evlog.test.ts tests/mcp-surface.test.ts tests/agent-http.test.ts`, `pnpm typecheck`, `pnpm build`. Then `node scripts/verify-logging-foundation.mjs` exercises the real built Nuxt HTTP/MCP/drain/query seam using a new temporary synthetic DB and emits an evidence directory. Optional `LOG181_FULL_MOUNT` must point to a dedicated disposable, bounded filesystem; the verifier intentionally fills it until ENOSPC and removes its own filler afterward. Never pass a production or shared filesystem. `pnpm verify:prod-openapi --skip-build --port <unused>` must also run with isolated `NUXT_DB_PATH`, `NUXT_LOG_DIR` and file directories.

This is foundation evidence, not domain instrumentation, UI/390px, Docker/Linux runtime, CI, production, throughput/SLO or parent-spec acceptance. Those lanes remain separate.

For a very large capacity decrease, bounded pruning may return409 `policy_capacity_pending`; the prior policy remains active until the physical store fits the new budget. Repeat the desired policy or explicitly clear a reviewed range first. Pruning already completed remains counted. Expired events are always excluded from reads even when physical age cleanup has a backlog. Status also separates the single in-flight batch from queued entries/bytes.

The module's response formatter is omitted because it changes existing API error JSON and headers. `server/logging-error-handler.ts` uses Nitro's own default JSON handler with raw stderr output suppressed; the official module's error event/drain hooks remain active. HTML error rendering continues through the existing Nuxt chain.


## Browser failure references and native-module packaging

Client intake accepts only the fixed kind/page/level vocabulary, optional static interaction (`task_artifact_download`, `task_cancel`, `task_retry`), and optional `relatedRequestId`: 1–128 ASCII identifier characters, never coerced or truncated. Intake stores the latter only as `untrustedRelatedRequestId`, separately from server-generated event/intake requestId/traceId. The shared sanitizer retains it only on source=client; detail/copy label it UNTRUSTED. It is not a trusted execution identity or query filter. Task download/integrity and cancel/retry catches report via the official evlog HTTP transport; response x-request-id is read when available, without error/body/DOM serialization. Delivery faults and log-reader failures do not report themselves. Classification-based dedup remains bounded to84 possible keys; varying request references cannot enlarge it.

The dev Rollup transform resolves logging's better-sqlite3 filename from the project at build time, including external NUXT_BUILD_DIR layouts. Production retains chunk-relative native-module resolution so packaged output remains relocatable. Source-only worker resolution is unchanged; no runtime deadline is extended.

Evlog uses the same allowlist as its runtime redaction transform before output, with generic string PII maskers disabled only after that projection. Generic credit-card/IBAN patterns can otherwise rewrite a valid generated UUID; the final identifier validator then removes it, breaking response-to-event correlation. Raw headers/body/URLs/error text are removed by the projection rather than retained for pattern matching. Main and worker pipelines share this policy; normal HTTP/MCP error and audit contracts are unchanged.
