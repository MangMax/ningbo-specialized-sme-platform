# 公布优先、平台兜底，资格判断与差异处置分离

状态：业务方向由用户于 2026-11-16 明确；本 ADR 的目标边界已记录，具体 schema、接口状态语义及迁移实现仍需按独立切片验证。

当前模型把平台接口降为差异解释证据，又把接口资格绑定在“已确认迁入”的差异决定中，使已有有效期间的企业仍被判为未认定。改为按企业、称号、周期及判断时点，优先使用公布依据，再以平台认定目录、关联办理记录、申报记录兜底；此路径适用于所有企业，不要求先办理差异核对或人工填写一份资格期间。Excel 导出是认定目录的批量比较快照，不是比接口更权威的独立资格来源。

## 名单发现顺序与资格依据顺序

平台接口不能直接返回全部企业名单。正常工作流是定期取得最新平台导出 Excel，与公布名单比较以发现需要查询的企业，再定向调用接口补充事实，更新差异解释和当前资格。

因此保留 Excel 导入、导出批次与差异发现入口；不改为“先从接口拉取全量企业”。接口按已知企业返回的局部完整结果，不代表全平台名单完整。采集顺序靠后不降低接口作为资格依据的优先级，补充采集也不是新增一次人工核对手续。

已经取得的公布与接口事实可以直接裁定资格，不把上传新 Excel 作为每次查看资格的条件。

## 普通界面的业务表达

公布资料、认定目录、关联办理和申报记录以同层级的业务来源呈现，显示各自时间线及对应的认定、复核或办理事件；资格计算仍采用前述来源优先级。用户不需要绑定接口行、确认对应关系、核对查询结构或阅读原始 JSON 才能使用接口资格。

同一企业、称号、周期的来源事实由系统归组，认定事件标明来自公布还是平台，不把接口记录伪造成公布历史。界面区分业务发生时间与资料采集时间，相同内容的重复采集不制造新认定事件。缺少公布事件的迁入企业可以直接呈现平台认定及期间，不显示“未绑定所以待核”的前置流程。

原始报文、内部编号、内容版本、归档及审计继续留存于后台，不作为普通用户页面的原始查询浏览器，也不为保留技术追溯另加一条用户必经流程。

## 所有权与取舍

- 公布历史保留在公布事件及出处中；平台记录继续由各自接口的业务记录、版本和采集观察拥有。资格域读取来源事实并计算结果，不把接口行伪造为公布事件，也不为正常资格另建人工确认账本。
- 迁入、迁出、注销等主体和地域事实与称号资格分开；迁入不是一次认定。相同信用代码且称号、期间和属地明确的接口记录不以名称变更、缺少宁波公布行或未办结差异解释为由拒用。
- 来源优先级适用于可用的当前依据及同一业务周期，不是“历史上只要有任何公布行就停止”。旧公布期间结束且无当前结论时可使用后续平台依据；同周期明确失败、取消及已确认的排除处置不能被陈旧接口标记绕过。独立新认定可建立新周期。
- 认定目录优先于关联办理，关联办理优先于申报。待审核、资料更新、终审通过分别按接口与事项解释，不因有一条记录或一次更新就重算认定年。明确期间优先；仅在业务年度语义明确时应用已确认的年度规则，不从采集时间猜年份。
- 版本、身份、字段解析及日期范围属于自动来源处理，不是人工资格审批。确定身份的记录自动参与；确有身份歧义、缺字段或业务冲突时才报告具体问题，不生成全体企业的待核对前置流程。
- 公布名单与平台快照的差异是来源比较结果；当前资格是独立派生结果。资格成立不抹掉原始差异，差异存在也不自动表示资格无效。差异说明或处置不会审批、撤销正常接口资格。

## 相对旧决定的修正

本决定替代[早期生命周期模型](2026-10-16-roster-lifecycle-model.md)中“导出表是平台现状、接口仅供解释”的资格来源划分，并修正[分域提案](0001-source-domain-boundaries.md)中可能据此形成的资格准入门槛；业务身份、原始来源、内容版本及公布历史分开保留的不变量继续成立。

[称号周期处置决定](2026-11-16-title-cycle-disposition.md)的周期处置、主体边界和高梯度继承继续成立，但其把已确认迁入资格寄存在差异决定中作为正常入口的选择不再是目标模型。已有公开命令和历史回执不悄悄改义；后续实现停止正常路径对其依赖，并明确历史兼容与退役边界。

不采用逐家为接口事实复制一份 `currentQualification` 的补丁，也不把所有 `sfyx=1` 无条件当成有效：前者重复来源事实并保留错误办理门槛，后者丢失期间、称号、周期及明确否定事实。
