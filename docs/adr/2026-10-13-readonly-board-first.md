# 第一阶段:只读查阅看板(后续会加写路径)

> 状态（2026-10-25）：历史阶段已结束。基线已有受控导入、资料/事件/出处维护、平台归档及对应写入；“台账不被界面修改”不再是当前统一约束。当前能力见[总览](../data-model.md)，后续分域边界见[待审 ADR](0001-source-domain-boundaries.md)。下文保留阶段取舍原文，不授权恢复只读限制。

**第一阶段**交付只读查阅看板:把名录导入 SQLite,提供分页、筛选、统计与导出。**「只读」是这一阶段的边界,不是 app 的永久定位**——后续阶段会依次加入数据管理、比对分析、以及**文件上传**(见 [ADR-tus 上传落在 app](./2026-10-14-tus-uploads-in-app.md))。

**为什么先只读:** 当前最痛的是“手头几千家企业散在 Excel 与公布文件里、查不动、说不清”。先冻结读模型、让导入管道与数据模型稳定下来,后续加写能力时不必推翻它。

**写法约定:** 「只读」指的是**台账数据(企业/记录/事件)不被界面修改**;文件库(`app/files/`)的上传属于**文件写入**,与台账记录无关,不受此约束。凡新增写路径,都单独记 ADR 说明其边界。

**当时已考虑但未选:** 直接做全功能数据管理后台——数据来源本身仍不稳定(历史公布文件仍在补,整理版仍在迭代),过早开放编辑会掩盖导入管道的质量问题。
