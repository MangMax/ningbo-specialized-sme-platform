# OCR 的**成功页中转**落在页图目录里(`files/**/.*.pages/.ocr-cache/`)

票 14 的在线 OCR 通路(`POST /api/jobs {kind:"ocr"}`)在**部分页失败**时要能断点续跑。
这份 ADR 只冻一件事:那个「续跑中转」写在哪、命中判据是什么、边界到哪。

## 为什么需要它:一句可复现的故障

`runOcr` 原本把一份 PDF 的页结果**只放在内存**里,`persistPages` 只在**全页成功**时才执行
一次(整份原子替换)。于是并发提交撞上 Paddle 的 **HTTP 429** 时(4xx **不自动重试**,这是
刻意的边界),「12 页里成功 7 页、5 页 429」的下一步是:**7 页白识别(钱已花)、一份结果
都没落库,重跑从第 1 页开始、把那 7 页再发一遍** —— 而重跑正是最容易再次限流的动作。

实证:`acceptance/20261015/fresh-flow/db/fresh.db` 两份 PDF(20 张页图)真实 OCR 三轮,
每轮都有页级 429;`fresh-flow/evidence/ocr-429/finding.json` 记到 `freshDbOcrRowsAfterAttempts: 0`。

## 落点:源 PDF 自己的页图目录里

```
files/<source>/<kind>/<year>/<batch>/.<文件名>.pages/pNNN.png
files/…/.<文件名>.pages/.pages.json
files/…/.<文件名>.pages/.ocr-cache/<key>.json      ← 本 ADR 新增的写路径
```

与 [ADR-页图是派生缓存](./2026-10-14-page-images-as-derived-cache.md)同一口径、同一处:
页结果中转是**某一份 PDF 的**派生数据,跟着它的页图走。因此

- **目录名带前导点**:文件库扫描器(`scanFileStore`)按「`.` 开头即跳过」滤掉,中转条目
  **不会**被回填成 `stored_file` 里的「文件」;
- **一并被 `.gitignore` 的 `files/**​/.*.pages/` 覆盖**,不新增忽略规则;
- 删掉即可重跑(`removePdfPages` 连它一起清),**不建表、无迁移** —— 与票 14 的
  `ocr_result` 分得很清:那是**产物**(要入库,重建要花钱花时间),这是**加速件**。

## 写路径的边界(这就是本 ADR 要冻的东西)

- **只写 `files/**​/.*.pages/.ocr-cache/` 之内**。目录由服务端从**源 PDF 的相对路径**派生
  (`lib/pdf-page.ts` 的 `pageDirRelPath`),解析后必须仍在文件库根内(`resolveWithinRoot`,
  与页图渲染同一把关)。不碰源文件、不碰台账、不碰 `ocr_result`。
- **只存通路 a(在线 API)真的识别出来的页**。人工纠偏/上传(通路 b)与代理写回(通路 c)
  的结果**不进这里** —— 那是**人的判断**,不是「provider 对这个输入说了什么」。把它当缓存
  去顶替一次真实识别,等于把人的编辑悄悄固化成机器的输出。
- **命中判据 = 页图内容 sha256 + 模型 + 影响识别结果的有效选项指纹**
  (`ocr-api.ts` 的 `ocrRequestVariant`:模型 + 实际发出的 `optionalPayload`)。
  任何一项变了就是另一个 key ⇒ 旧条目**自然不再命中**,不需要谁记得去清缓存。
  页图用**内容哈希**而不是路径/mtime:重渲染换了 DPI 就换内容,那正是要重识别的时候。
- **读坏了当未命中**:缺失 / 半截 / 坏 JSON / 形状不对 / 身份对不上,一律重识别 ——
  宁可多花一次,也不把一条可疑数据当成结果。
- **写入是原子的且尽力而为**:先 `.tmp` 再 `rename`;写不进去只吞掉,不让一次**已经成功**
  的付费识别跟着失败(真实后果只是「下次重跑要多识别一次」)。
- **不改变结果语义**:`ocr_result` 仍是**一份全成功才在单个事务里整份替换**。中转只保证
  「重跑只补缺失/失败页」,不保证「部分成功也算结果」—— 后者会在正式结果里留下半份新数据。

## 已考虑但未选

- **建 `ocr_page_cache` 表**:一个纯加速件不值得一次迁移与一套清理策略;而且它的生命周期
  跟着页图(删页图即可重建),放进库反而多一份要自己对的账。
- **只靠 `ocr_result` 里已有页做续跑**:那正是**要避免**的 —— 人工纠偏过的页(channel=`upload`/`mcp`)
  会被当成「已经识别过」而跳过,于是人的修正挡住了真实识别。
- **在文件库根下集中放 `.ocr-cache/<哈希>/`**:要再维护一份「源 ↔ 缓存」映射,而映射本身没有
  新信息;也让「删掉这份 PDF 的派生数据」不再是一步。
