# 台账不保留导入快照/批次

数据模型里**没有** `import_batch`(导入快照)这张表,`record` 也不记录「哪次导入写入了它」。台账只表达**当前的事实**:企业、称号、来源、事件及其出处。原始来源文件路径已逐条记在 `record_evidence` 里,足以回溯。

**为什么:** 快照是为「切换到某次导入当时的记录集」引入的,但**没有任何页面或问题需要它**——看板要回答的是「现在有哪些企业、什么称号、哪一年认定/复核」,不是「8 月那次导入时是什么样」。多一张表、多一列外键、多一个筛选参数、多一个 `/api/batches` 端点,全都是无人使用的复杂度。

**后果:**
- 幂等改由**身份键去重**保证:企业 `(uscc_norm)` / `(name_norm)`、记录 `(enterprise_id, title_code, source)`、事件 `(record_id, event_type, year, batch_seq)`。重跑同一目录,逐表行数不变。
- 数据的「时间」语义全部落在**事件**上(`record_event.year` / `batch_seq`),而不是「加载时间」。
- 迁移 `0001_married_mister_fear` 删除 `import_batch` 及三处 `import_batch_id` 外键。

**已考虑但未选:** 用快照做逐年对比——真要做,正确的轴是**事件年份**,不是加载批次。
