# 称号周期处置与迁入资格确认

2026-11-16，用户在规格 #738 实施中确认契约扩展。称号周期处置由独立的、有类型的修订与回执协议维护，资格领域统一消费；不放入企业迁移事实或差异办理的单一 head。它引用原企业、称号、周期和不可改写来源，区分未申请、未推荐与正式复核失败。正式失败仍由正式事件拥有，不复制正式事件。相较扩展差异决定 JSON，这一选择避免普通解释替换资格事实，也允许不同周期分别撤回和重新判断。

处置的发生与资格效果分开：未申请或未推荐不自动提前终止当前期间，只在已核实的生效依据和适用周期内影响资格。周期、生效时间或来源不完整时保留未知，不猜填、不据此新增排除或延长资格。正式新认定进入新周期，旧周期处置不能永久排除企业。撤回或来源变化后重新计算仍成立的依据，不直接宣布有效。来源变更保留旧审计并要求重新核实。

处置协议复用既有预检、原子提交、版本冲突与幂等回执模式，严格 HTTP/MCP 同源；当前资格读取采用优化后的批量输入和版本依赖，不建立第二资格引擎。存储与领域命令、公开协议、共同读取分别交付；不以协议交付冒称真实名单验收。

已确认迁入资格继续使用现有资格决定的称号和期间存储，另补最小公开预检及提交时来源版本校验，保持历史请求和回执的原语义。迁入事实不等于资格事实；城市、期间和来源版本各自核实。真实来源缺口单独跟踪，不能由平台有效标记或合成夹具补齐。

规格、切片计划与验收记录在 GitHub #738、#739、#741、#742；私有原件、数据库和报告留在 Git 外。
