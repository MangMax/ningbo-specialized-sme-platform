# Excel 读取适配（#148）

`readPlatformExport` 与 `parseLittleGiantWorkbook` 使用固定版本
`documonster@0.20.2` 的 `documonster/excel` 公共命名空间。
文件身份、首张工作表选择、列位、行号、原字段、警示和领域规则沿用原契约。
缺文件、损坏包、缺工作表均抛错；有效的空工作表仍返回空解析结果。

`lib/excel-read-value.ts` 只适配原读取器已使用的单元格值：

- 富文本、超链接、合并值、普通数字和布尔值继续交给原文本转换规则。
- 不执行公式，也不推算缺失缓存。ExcelJS 4.4 读取时省略的公式缓存
  `0`、`false`、空字符串保持旧的非空未知文本 `[object Object]`。
  普通单元格的 `0`、`false` 仍分别是 `0`、`false`。
  这是迁移兼容行为，不表示这些缓存不存在，也不把未知值改为空值。
- 现代数字日期和 1904 纪元保持原结果及毫秒舍入。平台表仍输出 ISO 日期，
  小巨人表仍使用原来的 `String(Date)`（含运行环境时区）。

## 早期数字日期

0.20.2 的普通读取模型把 1900 纪元数字序列 60 和 61 都暴露为
`1900-03-01`，`Cell.getDateParts`、`Cell.getModel` 也已没有原序列。
旧库分别暴露 `1900-02-28`、`1900-03-01`；旧库本身不是日历正确性的标准。

公共 `Stream.WorkbookReader` 的 `styles: 'ignore'` 选项仍保留原始数字及
公式缓存。适配器先检查实际使用字段中的早期日期，只在需要时用同一份输入字节
进行这次无样式读取，并按工作表名和单元格位置恢复数字。
这不是从已转换的日期反推序列，也不依赖 ZIP 内工作表出现顺序。
合并从单元格使用公共模型中给出的主单元格地址；读取迭代器完整消费，释放库的
延迟工作表资源。小巨人 A:J 以外的字段不参与日期适配。

恢复到原始数字后，保留旧读取器的线性纪元和毫秒舍入，包括虚构闰日的旧输出。
因此序列 60 与 61、负数、零、时间部分及 1904 纪元无需拒绝或猜测。
遇到需要恢复但原始数字确实不可取得的日期，则带表名、单元格地址抛错，
不会返回成功空表或将其置空。
没有运行时 XML 解码器、上游补丁或 ExcelJS 回退。

两个公开解析入口使用独立 ExcelJS 夹具验证富文本、公式、空值、坏文件和表选择；
日期包含两纪元各九例的普通值及缓存值，另覆盖早期日期合并、时间部分、负数
1904 序列和反向 ZIP 工作表顺序。真实四文件的完整原字段、规范化结果、顺序、
问题和元数据对照记录留在 Git 外；源文件、业务数据和测试证据不随代码提交。

共享依赖由 #146 合入。本切片初次返回不修改 package/lockfile；待 #146、#147
合入后，#148 再核实生产引用、将独立 oracle 使用的 ExcelJS 移到开发依赖，
并完成组合构建和包审计。读取适配测试不能替代最终 HTTP/隔离数据副本验收。
