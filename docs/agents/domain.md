# Domain docs

## Layout

Architectural and domain decisions live in `docs/adr/`.

## Before exploring

Read the ADRs relevant to the area being explored. Use the current schema, types and API contracts for implementation details.

Before changing the app shell, navigation, files, jobs, logging, settings or credentials, read [the platform core and business module boundary ADR](../adr/2026-11-17-platform-core-and-business-modules.md).

Use consistent domain vocabulary in code and GitHub Issues. Resolve ambiguity against the source-specific facts and relevant ADRs.

If a proposal conflicts with an ADR, name the ADR and explain the conflict explicitly rather than silently overriding the decision.
