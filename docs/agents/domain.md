# Domain docs

## Layout

This repo uses a single context: `GLOSSARY.md` at the repo root and `docs/adr/` for architectural decisions.

## Before exploring

Read `GLOSSARY.md` and the ADRs relevant to the area being explored. If a document does not exist, proceed without requiring its creation.

Use the glossary's vocabulary in specs, tickets, test names, and implementation discussions. If a needed concept is missing, reconsider the terminology or note the gap for domain modeling.

If a proposal conflicts with an ADR, name the ADR and explain the conflict explicitly rather than silently overriding the decision.
