# 存储与表结构约束

- **审批表结构。** 新增任何表（含审计、回执、归档、见证及修订表），或给现有单表新增超过 5 列时，先列出表名、核心列及实际读写它的 UI 或 API 路径。获得用户明确同意后再写迁移。表名使用业务术语，禁止以 Issue 编号命名（如 `*_113`、`*_669`）。
- **同一份数据只存一次。** 对应关系、审计、导入回执和任务结果使用外键引用与简短摘要。禁止重复内嵌上游原始响应、完整查询体或整块源对象。业务确需不可逆的时点快照时，只存一份，并说明为何无法由外键还原。
- **外部载荷去空、去重。** 持久化外部接口 JSON 前移除值为 `""` 或 `null` 的键，文档明确要求区分时保留。按内容去重，每份载荷只保留一份。
- **迁移收尾。** 迁移一致性的核对结构限于迁移过程。禁止在生产表或运行时代码中保留用于该目的的 `legacy_*`、`witness_*`、`reconcile_slot_*`、`fingerprint_basis`、`*_sqlite_storage`、`stored_*_kind` 或 `parsed_*_kind`。切换验收完成后删除一次性迁移脚本。
- **限制日志和任务体积。** 运行日志默认最低级别为 `info`。禁止将 `/api/health`、高频只读轮询和 `debug` SQL 落库。每份日志内容只存一份，每张日志表至多 5 个索引。已完成任务和回执使用有界结果摘要，并定义保留期限与清理方式。
- **替换旧路径并测量体积。** 用新实现替换旧路径时同步清理旧实现、并行投影和空壳表。涉及表结构或存储重构的验收报告须附 `pg_database_size` 实测值和按总占用排列的 10 张最大表。
