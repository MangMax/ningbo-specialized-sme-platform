## 实现与语义边界

- 列表先在 SQL 中按名称/已确认别名/统代搜索及有效属地缩小企业范围，再投影企业×称号的首次年份、认定/来源存在性、同记录同事件筛选和差异计数。首次年份使用 `decided_year ?? year`，同年取最小事件 ID，出处只做存在性判断，不载入所有出处字符串。没有解释的企业按既有规则使用 `not_queried`/空原因，直接分组计数；仅有解释的企业需要最新版本和状态优先级窗口。非空 `enterprise.uscc_norm` 的精确键比较依赖**既有 UNIQUE 约束**；空统代的两侧记录仍分别构成差异。
- 计数覆盖全部命中企业并先于分页。Node 仅保留前 `page × pageSize` 个排序候选；名称继续使用原 `localeCompare`，最后以企业 ID 打破并列。所选页一次批量读取身份、记录、事件、别名、出处，仍由原生命周期和首次认定函数生成完整行。导出共用选择器保持不分页语义，但本轮没有扩展为全量导出资源验收。
- 详情继续保留关系归属、查询键覆盖及解释证据的并集。普通 ASCII（含小写/标点）键和无特殊字符的中文名称留在 SQLite；Unicode 大写、空白、不可见字符、括号、尾部标点和嵌入 NUL 仍调用原共享 normalizer。没有修改原始身份值。
- `normalizeUscc` 会把 `name:` 转成 `NAME:`，因此不可能匹配原有小写 `name:` 键：该查询分支只保留原精确名称匹配；无统代企业不再扫描归一化查询键。归一化不会删除 `:`；目标统代不含冒号时先排除含冒号的无关键，目标本身含冒号时不使用此预筛选。关联到企业的查询仍独立纳入，不依赖键匹配。
- 列表选择、统计和页内补齐仍在同一 SQLite 读取事务中。相关原始 JSON、全部 recognized 原行（含未匹配主体）、五态、出处位置、生命周期和差异解释不截断。企业读路径不使用已合入的 #89 平台摘要缓存。

## 未满足项与最小下一步

列表已经消除全量 JS 生命周期/证据聚合和全候选保留，但无过滤的精确统计仍需扫描轻量历史并在 SQLite 中分组。当前同步驱动会把这些原生计算放在应用事件循环上。索引不能使同步长调用变成异步；不能通过增加 worker/堆、超时或查询结果缓存隐瞒这一点。

因此仍需以最终矩阵列出的实际失败为准，不能宣布 #84 完成。最小下一步是专门实现并验证企业 HTTP/MCP 共用的**有界异步执行接缝**：保持每请求独立一致读取、固定并发/背压、提交后即时可见、无结果缓存；跨执行边界的原文传递必须同时核算总堆和复制字节，继续满足原文2倍字节+64MiB预算。若继续保持本轮同步执行契约，事件循环门槛不能据当前结果验收通过。
