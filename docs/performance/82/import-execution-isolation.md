# Import execution isolation

HTTP and MCP preflight/commit execute the existing import core in one serial native child. Authentication, request validation and evidence-page validation run before admission. The original receipt reservation, business transaction, expected-revision checks, idempotency and SQLite durability settings are unchanged. Explicit evidence replay keeps its existing implementation. No UI changes are involved.

Admission counts the active command plus FIFO entries: at most **8 commands** per application instance. The **32MiB V8 binary-serialized request budget limits concurrent backlog, not the size of one batch**. When empty, the executor admits a larger validated batch exclusively; while its retained payload exceeds the budget, later requests receive HTTP503 `import_busy`. Otherwise another command is admitted only if the combined retained bytes fit. Rejection precedes worker dispatch, receipt reservation and business writes, and retry can succeed after admitted work settles. MCP retains its existing tool-error envelope and transport-size contract. No batch is split. In-memory/explicit same-connection transaction callers retain their original core execution; file-backed requests never fall back inline after worker failure. Binary structured serialization preserves source fields and fingerprint rules. The prior single-batch rejection above32MiB was a compatibility regression: it made valid idle requests permanently busy. Regression coverage now includes actual encoded input above32MiB through HTTP preflight, commit, raw readback and same-key replay, plus exclusive and combined-backlog recovery. This budget does not promise arbitrary-size batches fit the existing child heap; the process resource limits below remain unchanged.

One worker owns at most one SQLite connection. It opens the already migrated file with FK ON and verifies the admitted realpath/device/inode, schema version and latest migration receipt before execution. It neither migrates nor changes journal/synchronous/busy settings. A replaced file/schema produces503 `import_source_changed` before business execution. Source identity checks do not lock the filesystem against external replacement; operational file replacement must still avoid a running application.

The child reuses the enterprise process boundary and explicit oldspace256MiB/semi-space16MiB. Main oldspace2048MiB and all benchmark1CPU/4GiB limits remain unchanged; main, enterprise child, import child and driver must be included in resource accounting. Queue input copying and child startup add overhead and are included in request completion.

Disconnecting an admitted HTTP caller does not cancel its command. Graceful shutdown closes admission, rejects new requests and drains accepted work before stopping the idle child. An unexpected child failure never automatically replays an active command. If COMMIT succeeded but IPC response is lost,503 `import_outcome_unknown` means read the durable receipt and retry **the same idempotency key**; it does not assert rollback. Startup failure fails its admitted request once, and a later request may start a new child after the old process exits. Independent instances retain SQLite's existing write contention behavior. Summary cache invalidation continues to use each observer connection's `data_version`, including external/child commits.

A regression holds a real second SQLite writer lock. The original main-thread HTTP implementation returns500 before its own timer can release that lock; isolation lets the timer run and commits300 rows with identical replay. Additional public HTTP regressions cover later-chunk rollback/retry, raw/sourceRowNo readback, foreign keys, queue overflow, graceful draining, client disconnect and a real post-COMMIT process death with deliberately lost IPC response. Focused correctness is distinct from the frozen controlled performance gates; performance acceptance remains open until measured on the new exact archive artifact. Historical misses remain retained.
