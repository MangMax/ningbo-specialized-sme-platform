## 公布文件的解析要点

一份公布文件 = 正文 + 若干「附件」段。**附件标题决定该段记录的称号与事件类型**(含“入库培育”即培育、含“复核”即复核、否则认定)。

- 一个文件可含**两个附件**(附件1 认定 / 附件2 复核),各自成记录。
- 一个附件的表格可含**多段名单**(如 2022 年文件把 2021 与 2022 两段并置,序号各自从 1 起),需按序号重启切段。
- 5 份公布文件的表格**无统代列**,只能按名称归并;其中 2 份是 `.doc`,需先转 docx。

## 粒度模型(原型验证)

**记录 = 企业 × 称号 × 来源**;记录下挂 **认定 / 复核 / 维护 / 入库培育** 事件,事件可有**多条**。

```
enterprise ──1:N── record ──1:N── record_event
                     │
                     ├── title (称号)
                     ├── source (经信局 / 工信部)
                     └── evidence ── source_file / attachment / list_no
```

**典型例子(实测)**:宁波博登智能科技有限公司
| 记录 | 称号 | 来源 | 事件 |
|---|---|---|---|
| 1 | 专精特新中小企业 | 经信局 | 认定 2023-1 **·** 复核 2026-1 |
| 2 | 创新型中小企业 | 经信局 | 认定 2023-1 |
| 3 | 专精特新中小企业 | 工信部 | 维护 2025-1 |
| 4 | 专精特新小巨人 | 工信部 | 维护 2025-1 |
| 5 | 创新型中小企业 | 工信部 | 维护 2025-1 |

## 归一化内核(纯函数)

导入前统一清洗,**区县**同样归一化(早期遗漏):

- 统代:`normalizeUscc` — 去空白/全角→半角/去零宽/大写;占位值(`#N/A`、`0`)与形状不符者视为无统代。
- 名称:`normalizeName` — 去空白与括号、去尾随符号;无统代时作归并键。
- **区县:`normalizeDistrict` — 修正错别字、省略写法与旧名**(如 `酆州区`→`鄞州区`、`象山`→`象山县`、旧名 `杭州湾`→**`前湾新区`**);`NINGBO_DISTRICTS`(12 区县)+ `NINGBO_INDEPENDENT_ZONES`(**独立管理区**:`大榭`/`保税区`,各有独立管理机构,是合法属地,不并入行政区)定义合法取值,`isNingboDistrict` 用于识别漂移。

> **口径(已定)**:`杭州湾` 是 `前湾新区` 的旧名(2021 年更名),来源里两者并存,统一归一化为 **`前湾新区`**(742 + 26 = 768 条)。
- 批次:`parseBatch` — `2024-1` / `2025年度第二批`;年份区间(`2021-2022`)识别为区间、无批次。

## 数据质量标记 `quality_flags`

| kind | 含义 | 是否可从源数据直接推出 |
|---|---|---|
| `uscc_missing` | 企业无统代,按名称归并 | ✅ |
| `name_ambiguous` | 重名(同名对应多个主体/多个统代) | ✅ |
| `district_off_city` | 属地不在宁波区县/功能区(漂移或写法异常) | ✅ |
| `deregistered` | 已注销 / 吊销 | ❌ 需登记状态外部富化 |
| 当前城市非宁波 | | ❌ 需外部富化 |

> 前 3 类由本台账直接推导并呈现在 `/quality`;后 2 类需接入登记状态/当前城市等外部数据,本期不做(见 [ADR-公布文件为输入](./adr/2026-10-13-announcements-as-input.md))。

### 统代回填与同一法人归并(pipeline 侧)

早期经信局公布文件无统代列、又不在工信部名单的企业,由 pipeline 按**企业名**从人工整理版回填统代(整理版仅作**定向回填源**,不作看板输入)。若回填的统代已属于另一条企业,则二者是**同一法人**(改名 / `有限公司`↔`股份有限公司` / 增删字),按统代归并记录。实测:无统代 **335 → 3**;归并同一法人 **123** 家。详见 `../pipeline/README.md`。

## 事件类型对照
| 来源 | 可能的事件类型 |
|---|---|
| 经信局 | 认定、复核(可多条)、入库培育(仅 2021) |
| 工信部 | 维护(取维护批次;名单不分认定与复核) |

## 已知口径待定(待确认)
1. **多次事件**:同一企业同一称号可在不同年份多次认定/复核(公布文件里本就是多条列表),模型以 `record_event` 一对多承载,**不压缩成逗号分隔**。
2. **入库培育**:仅见于 2021 年入库培育公布文件,记 `nurture`,不计入称号有效期。
3. **经信局与工信部并列**:同一企业同一称号有两来源时是两条记录,看板需标明“双来源”而非重复。
