# 当前数据模型总览

本页按固定基线 `62a18027c9980a25f0aad4ffd4438564bc5c329b`（tree `5ee686dd08f09f0a5b09f8ec1e39f0914dde64a8`）描述已实现能力，并单列待评审目标。术语见 [GLOSSARY](../GLOSSARY.md)，52 表去向、14 组消费者与兼容顺序见 [分域 ADR](adr/0001-source-domain-boundaries.md)。本次仅修正文档，不代表迁移已完成。

## 已实现的责任与边界

应用已有受控导入、平台采集归档、企业资料维护、正式事件与出处更正、记录对应、年度过程、文件/OCR/解析维护和后台任务，不再是只读看板。HTTP/MCP 共用领域写入与校验；统一导入具有预检、提交、幂等批次及回执，各专用维护入口按自己的契约工作。旧 [生命周期契约](roster-lifecycle-contract.md)保留历史协议细节，不能覆盖后续专用契约。

| 责任 | 当前载体与接缝 | 边界 |
|---|---|---|
| 企业身份与资料 | `enterprise`、`enterprise_alias`、资料/别名审计；现有企业资料 PATCH | 统代优先，别名保留来源；归属待核不强并，现用资料不代替历史原值 |
| 正式公布历史 | `source_document`、`record/event/evidence`；正式导入、事件/出处更正 | record 是企业×称号×发布方容器；事件、出处各有 ID，平台状态不改写正式事件 |
| 平台采集与原档 | `platform_query/relation`、称号索引；实时单查/批查、归档列表、精确原档 | 查询状态是采集结果，关系行是观察；查询条件不是每条业务的称号/年度事实 |
| 平台身份与历史 | `platform_business_record/version/observation` | 当前三来源按接口+业务编号隔离，版本与观察分开；缺键、冲突、不可核实显式保留 |
| 文件导出快照 | `platform_export_batch/row` | 保留文件版本与物理行；审核状态不同于工商登记状态，不替代正式历史 |
| 对应、差异与年度 | `record_correspondence`、proof、`difference_reason`、113/114 表及审计 | 决定精确到原观察/导出行；先限定来源范围再分组；年度完整过程与唯一 final 分开 |
| 当前有效资格 | `current-qualification`、优质中小企业查询与三称号工作簿 | 复用资格读取，待核/排除与有效分开，不另造资格 writer |
| 文件与识别解析 | `stored_file/part`、`ocr_result`、维护/解析审计 | 文件ID、路径、显示名、内容身份分工；已有页版本和解析输出版本，尚非完整输入血缘 |
| 任务与回执 | `job`、`import_batch/receipt` | job记录执行与业务载荷，任务中心当前仍集中适配结果；采完、归档、核对、资格裁定须分别理解 |
| 配置与运行日志 | `service_credential`；独立日志库3表 | 运行日志与业务审计分开，配置不进入业务 DTO 或 Git |

表名缩写仅为阅读方便，确切52表名见 ADR。正式附件是认定/复核依据，平台导出是采集时点快照，实时接口还承载申报、关联办理与认定目录业务，不能把平台只称为取证来源。整理版名录只作交叉核验/有依据的定向补码参考；未匹配平台导出的正式名单行仍完整保留。

业务数据库、原始文件、上传件、凭据与过程证据在 Git 外。出处路径按配置的文件库根解析，`files/` 相对路径不是文件随源码提交的授权。

## 三种现有查询分别回答什么

- 实时 `query_platform`：上游在本次条件与时点返回什么，包含未完成范围。
- 本地归档 `list_platform_queries` / `GET /api/platform/queries`：留存过哪些查询、原行与观察历史。
- 现有优质中小企业查询 `GET /api/roster/current-enterprises` / `list_current_qualified_enterprises`：本地规则下当前确定有效且匹配筛选的企业，页面为 `/current-enterprises`。

三来源各自的有类型本地业务查询是下一步目标，不能将归档列表更名即宣称已交付。现有查询与 [三称号异步导出](current-roster-export-contract.md)复用资格规则；查询返回确定有效匹配，工作簿另有待确认/排除明细，输出形态不同不等于资格规则不同。来源字段的已验证投影按现有契约限制，不把 `queryBusList` 的某称号/格式规则推广到其他来源。

## 待评审的增量目标

[分域 ADR](adr/0001-source-domain-boundaries.md)在 #297 冻结设计边界，等待父线程对提交后的候选进行新鲜 Spec/Standards 审查；两者无阻塞前不解锁依赖模型任务。

| 目标责任 | 最小增量 | 保留的基线 |
|---|---|---|
| 申报/关联办理/认定目录 | 各自专用业务字段、状态、年份含义与可索引本地读契约，按内容版本关联投影 | 复用业务身份/版本/观察；旧 relation 停止扩为万能业务表 |
| 正式出处原值 | 实际文件内容版本与出处行保存原名、原统代、原属地及坐标，独立追加佐证 | record/event/evidence ID、原定位、更正和审计；record 第一份原值不能代表所有年份 |
| 主体迁移/状态断言 | 有来源、时点及明确确认/撤回的独立事实，差异决定引用事实 | 企业资料 PATCH、差异历史，不自动恢复旧迁移解释 |
| 识别解析输入血缘 | 文件内容→OCR采集/校对页修订→解析输入清单→输出；提交重核输入及目标版本 | 文件ID、页版本、解析回执；旧输入依据缺失记未知 |
| 周期裁定与消费者 | 共用原认定周期裁定，逐消费者切换来源专用读取 | 首次认定、复核计划、当前资格仍为不同输出；复用已有查询及导出 |

审计反例与设计缺口不能写成已发生的生产事故。当前资格已有失败恢复保护，历史原文/回执可能仍保留原内容，旧 full 比对问题不能泛化到所有页面。

## 年份、原值与决定

原认定年定位被认定批次，办理业务年属于实际办理事项，公布结论年是正式结论发生年；采集年、维护年与本地到期年另有含义，不能互填。复核 `record_event.year` 是被复核原认定年，`decided_year` 是结论年；缺失留未知。

原值、已验证规则得到的规范字段、本地确认值并列且可追溯。原始 JSON 缺键、null、空串、数字、布尔及对象不相互替代，规范化冲突不能支持正面结论。旧字符串化输入不反推类型，不重算历史 hash。

来源代次变更继续进入113影响登记与114明确复核。新版本、同hash、同编号或同企业不传播 proof/确认；拒绝、解除、更正、替换、撤回及审计均保留。
