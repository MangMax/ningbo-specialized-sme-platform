# T02 immutable archive internals

#709 adds an evidence-only internal module, `lib/platform/immutable-archive.ts`. No HTTP/MCP route uses it yet. `insertArchiveValue` accepts original SQLite storage class and Buffer bytes, computes SHA256 and length, and optionally validates independent expected values before insertion. SQL NULL has no bytes/length/hash; text `null` is four bytes; zero-length text/blob is valid. The archive digest is not a replacement for any historical business fingerprint or content hash.

Three typed reference tables restrict fields and owners with real FKs. Each archive belongs to one owner-field globally, including across reference tables; values are never deduplicated. `writeOwnerArchive` inserts and binds atomically and composes with an outer synchronous Drizzle transaction. Callers insert the complete field set in that transaction, then `sealArchiveOwner`. An owner must have at least one binding to seal. A present SQL NULL field gets its own archive row; an absent field has no binding. Binding replacement/deletion is prohibited even before sealing; the only supported reference UPDATE is 0→1 seal with every other column unchanged. Once any reference is sealed, additional fields are rejected. Repeated seal is rejected. A correction requires a new explicit owner/revision under the owning domain's contract.

The migration installs UPDATE/DELETE rejection and BEFORE INSERT collision checks. The INSERT checks are necessary because SQLite REPLACE can delete silently when recursive_triggers is off. They cover PK and unique-target collisions; upsert cannot change immutable values. Archive and alias rows have no generic removal API. SQLite constraints validate storage class/length/hash shape; digest equality is validated by the insertion service (SQLite has no built-in SHA256 function). Direct arbitrary SQL that bypasses this service is not a supported archive insertion interface.

`readArchiveValue` and typed `readOwnerArchive` return at most 65,536 bytes per read, with base64, offset, totalBytes, isNull, byteLength and hasMore. Missing archive/binding is null, distinct from present SQL NULL. BLOB substr runs in SQLite and may split UTF8 code points. Callers concatenate decoded chunks before interpreting text. No full BLOB is loaded for range access. No JSON is parsed or reserialized and no archive business fallback exists.

## Explicit observation transition

The existing observation's PK/FK is still `platform_business_observation.relation_id → platform_relation.id`. T02's observation refs and relation alias point to that existing observation PK, not a new observation table. Relation alias insertion checks that an existing observation joins its original relation and a mapped legacy query. Pair resolution joins that same relation and requires its actual query_id to equal the requested query alias. Same integers in different namespaces are insufficient. Missing mappings return null. This narrow transitional relation JOIN is owner verification, not a legacy business reader. T03 must rebuild these FKs and the ownership JOIN against collection_id when it replaces observation identity; this document does not assign or implement T03.

Alias rows are immutable and targets unique. `reserveLegacyIds` requires frozen source query/relation ID maxima, validates existing alias maxima and refuses rewinds. `allocateLegacyAlias` requires prior reservation, advances a namespace's water mark and inserts the target alias in one transaction. It also considers existing mapped IDs, rejects safe-integer exhaustion and rolls back water marks on target conflicts. New compatible external IDs are strictly above reserved old IDs; query and relation namespaces remain separate. This does not allocate or rewrite business record/version IDs. Final observation/internal sequence transfer belongs to the observation/historical-transfer stages, with their frozen manifests; T02 never writes a new legacy relation or migrates source data. Original version canonical TEXT and historical content hashes are unchanged.

## SQL exceptions and verification boundaries

Normal inserts, updates, lookups, aggregates, joins and transactions use Drizzle 0.45.4. `substr(bytes,start,length)` is the narrow SQLite BLOB range exception; DDL triggers enforce invariants Drizzle schema declarations cannot express. Migration SQL and test-only PRAGMA/sqlite_schema/frozen old cast+DTO expressions are infrastructure/oracle exceptions. Generated 0048 schema and metadata extend accepted 0047 without rewriting earlier SQL or snapshots; trigger DDL is appended explicitly because drizzle-kit does not generate triggers. No alternate schema generator or JSON business-query expression is introduced.

The frozen test DTO uses the old SQLite json_object column order/json(raw_fields) semantics, including SQL NULL and malformed JSON errors. It proves old behavior and archives its literal bytes in an isolated fixture; T02 does not implement the complete mutable-assignment relation serializer or route cutover. C3 owns public evidence integration. Historical source transfer, provenance conversion, runtime writer migration, observation reconstruction, assignments, public consumers and table retirement remain separate deliveries.
