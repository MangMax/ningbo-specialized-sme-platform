# T05 prerequisite: uncaptured observation indexing (#714)

This is a schema prerequisite on accepted integration `15325ccc7a62875f6aa991cb995d600094f22082`, not acceptance of #713 candidate `a8007874` or a runtime cutover. It completes the missing expression in the accepted retirement contract: every old relation must eventually retain an observation even when no indexing facts were captured.

The same observation table now admits `identity_state = content_state = 'not_indexed'`, reusing the existing read-side state in `lib/platform/business-record.ts`. In this branch record/version/key source/projection rule/input fingerprint/indexed time must all be SQL NULL. Missing key, conflict and unverifiable remain results of an actual indexing attempt; none substitutes for uncaptured indexing. Batch and collection mapping remain independent capture metadata. No parser is run by this migration, and no observations are invented or transferred.

The indexed branch retains resolved/missing_key/conflict, verified/unverifiable and the matching version/record FK. Its key source must be a recognized non-null value; rule, fingerprint and indexed time must be TEXT. Explicit IS NULL/IS NOT NULL and typeof checks prevent SQL CHECK's NULL result from admitting mixed states. Existing empty/whitespace rule, hash and time text are retained verbatim. There is no SQL time default. The existing ORM indexed-writer time default remains for compatibility: an uncaptured ORM insert **must explicitly pass `indexedAt: null`**. Omitting it is rejected, never persisted as a fabricated historical time. The time of a future indexing operation is technical indexing metadata, not the historical observation/confirmation time.

`PlatformObservationProjection` remains the indexed-writer result. The three isolated-list DTOs accept the already established read metadata state; record detail queries exclude not_indexed via record_id. Metadata/grouping already keep not_indexed observations separate. No parser, list predicate, runtime writer, reader selection or domain rule changes. The existing writer intentionally refuses reinterpreting an observation with unknown fingerprint/rule; enabling future indexing is a separate owner decision.
