# #725 C offline capture and certification seams

Only explicit isolated 71607 targets are certified. Startup, ordinary runtime and worker nonzero-phase guards are unchanged. Existing 71605/71606 writer behavior remains available for predecessor/offline tools; there is no implicit schema upgrade. Complete collection commands accept explicit 71606 or 71607. Public HTTP/MCP routing is unchanged.

The three source writers capture the exact `{collectionId, position, row, assignment}` canonical UTF-8 buffer before observation insertion, including missing identity/version observations. The same buffer supplies the original SHA256 and an exclusive immutable BLOB basis. `nextObservationId` checks the physical observation maximum and sqlite_sequence highwater before incrementing. Basis/archive, observation, assignment revision1, projections, aliases and allocation changes share the writer's nested transaction. Reuse compares the original immutable basis without inserting another one.

`captureFingerprintBasis(db, observationId, scheme, bytes)` is a low-level basis-first helper for already serialized evidence. It requires actual FK ON and phase 71607. It does not certify arbitrary caller-supplied bytes. Its deferred observation FK is checked only at the outer COMMIT. A nested RELEASE and a writer return are provisional while a caller transaction remains open. The outer owner must COMMIT and explicitly roll back on failure.

`verifyFingerprint(sqlite, {observationId, collectionId, relationAlias})` authenticates one explicitly selected owner in a single read snapshot. Call it separately after both planned and exact-original selection. It refuses missing/uncaptured/unknown basis and validates archive ownership, bytes, original hash/rule, coordinates, mapping, original source/version projections and revision1. Current assignment revision2+ remains independent. Command verification shares the accepted S fact-checking logic, staged in an empty in-memory copy of the physical schema; business parsers remain in their original writers. Canonical input sorts keys, so sealed raw JSON is used to restore only JSON.stringify insertion order after canonical equality is proved. This cannot recover omitted/null/extra input keys; those come exclusively from the captured basis.

`bootstrapFingerprint(sqlite, owner, 'ordinary' | 'reference')` handles paired not_indexed observations. Reference mode returns null without indexing. Ordinary mode validates full original cells/raw/source/aliases and observation projections, stages original source-writer indexing, then atomically installs a legacy-bootstrap basis and first index. Collection request existence does not select the scheme. It retains original archives, assignment revisions and aliases. Existing indexed observations go through certification, never recapture. Both bootstrap and every supported target archive/alias helper reject FK OFF before writes, including when an outer transaction already exists.

Certification failures expose `kind='platform_relation'`, `ref='relation:<alias>'`, `field='relations'` and `code`. Source/rule/hash faults use `projection_source_drift`; indexed mapping faults use `projection_mapping_conflict`. The importing caller remains responsible for its normal result envelope.

#722 still owns migrated F1/rule, complete plan-to-actual mapping F2 and final ordinary/reference replay wiring. This module does not replace those checks, consume the rejected candidate or authorize routing. S recovery still requires its independent frozen source/event evidence. Captured basis alone does not authenticate real historical provenance. Historical FAIL and UNKNOWN remain, and no real database or production switch is accepted here.
