# T03b source projection expansion (#711)

This is schema expansion only. No historical row is interpreted or mapped. T05 transfer, W1–W3 writing, R1–R3/H1/H3 consumption, final FK promotion and public acceptance remain separate work.

Each existing source projection now has an internal autoincrement `id`. `version_id` remains unique and keeps its composite version/record FK. Old writers omit `id`, `basis` and every new field: the default `verified_raw` selects the version branch. Observation rows instead have a unique `observation_id`, NULL version/record and `observation_reconciliation` or `unavailable` basis. Shared verified content never replaces an observation row. During expand this FK points to observation **relation_id**, while source ownership is checked against its explicitly mapped collection.interface. An unmapped observation cannot acquire a projection by guessing its source. T05 must rebind to final observation.id and preserve existing values.

The three tables each carry the seven legacy normalization fields: province, status, batch, declare_kind, applied_at, award_batch_label, year. `stored_*_kind` describes the original stored input type, `stored_*` its old comparison value; `parsed_*_kind` describes source input type and `parsed_*` its old process parser comparison value. Allowed kind markers are absent/null/text/number/boolean/array/object/invalid. Missing/null/invalid/non-scalar comparison values stay NULL; whitespace text may compare as NULL without losing its original type. The original complete value remains in the immutable archive, never reconstructed from normalized columns. `reconciled_*` and INTEGER 0/1 `*_conflict` enforce the literal nonnull disagreement/coalesce algorithm. Years are safe integers, including historical zero/negative stored facts; this schema does not invent parser success. Source-specific extraction and validation of kind against original bytes belong to transfer/ingest, not SQL JSON fallback.

Recognized rows must have all seven parsed process fields absent/NULL: queryBusList does not use processFactsFromRow. Its old stored year is distinct from maintenance_year. Existing source_validity_date, source_maintenance_batch and source_maintenance_year_absent retain NULL/false/empty/space distinctions; the old global 0/1 CHECK is preserved. These comparison columns do not authorize archive supplementation: withArchiveProcessFacts still requires a nonnull version, an explicitly modeled nonnull field and no conflict. Schema does not change that consumer.

`source_title_kind` separates absent/null/text/number/boolean/array/object/invalid. Only text has untrimmed source_title_text; only number has source_title_number_text; only boolean has INTEGER source_title_boolean 0/1. Numeric tokens must be numeric JSON text, without surrounding whitespace; the transfer/ingest boundary must generate **String(decoded JS number)** as required by the accepted contract (SQL alone does not implement that JS serialization). The old normalized title_raw remains independent. Extraction lineage uses source_title_rule_version and source_archive_id, checked against the same observation's sealed T02 rawFields ref. parse_state valid requires observation_reconciliation; invalid/absent require unavailable. Unknown facts are not normalized into empty valid facts.

Version `canonical_archive_id` is nullable during expand to preserve populated old versions and writers. When supplied it must match that version's sealed T02 canonicalRawJson ref; it cannot subsequently be removed or replaced. This reuses platform_version_archive_ref and platform_archive_value, with no duplicate archive facility. A future writer inserts the version, binds/seals its T02 archive, then sets canonical_archive_id in the same transaction. canonical_raw_json stays required and unchanged until the explicitly owned transfer/cutover ticket. No archive fallback is added.
