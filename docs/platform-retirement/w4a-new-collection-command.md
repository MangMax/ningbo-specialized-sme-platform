# W4a complete new collection command

`writeNewCollectionTarget` in `lib/platform/collection-target-command.ts` is an explicit synchronous 71606 target command. Its executable consumers are the three-source finalized SQLite fixtures in `tests/platform-collection-target-command.test.ts`. No public routing or runtime guard changes are included.

Input is the original JSON query text (the existing import query contract), the separately retained original collectionEvidence JSON text or NULL, explicit per-row command assignments, and caller-supplied creation time. The existing Zod shape is exported without modification for validation; parsing does not replace original raw objects. Both observed documents must agree. `request` retains queryText bytes, `collectionEvidence` retains evidenceText bytes, and rawResponse retains the original decoded text value or SQL NULL. Business parsing remains with the three accepted source writers. Collection-level JSON extraction occurs only at ingestion. The migration0027 second-parse/text-only scope semantics use scalar SQLite JSON expressions; ordinary table CRUD is Drizzle. No old query/relation entity is accessed and no upgrade executor is imported by the command.

A nested transaction/savepoint contains collection, ordered pages, unfinished positions, ten condition fields, limits, same-table scope/error, three sealed archive refs, query namespace alias and the explicit interface switch to source writers. Output contains collectionId/queryAlias and each writer's observation/record/version/relationAlias result. ID/FK/CHECK and alias high-water failures throw and roll back this entire unit, even when an outer transaction catches the exception. No network awaits occur.

Source validation is the current platformEvidenceError plus the import identity/row/order/source/USCC checks. This intentionally rejects duplicate pages, invalid/missing required metadata, non-text conditions and mismatched raw rows; it does not normalize invalid observations into admissible new evidence. Thus the accepted new-input condition partitions are text and absent; null/integer/real/boolean/array/object are rejection cases, not alternate accepted contracts. The error table is still explicitly owned by this command, though a valid new typed envelope cannot produce a scope-error row. Historical malformed/JSON5/double-encoded scope inputs remain an offline upgrade responsibility, already independently covered by #720. Missing collectionEvidence is allowed for legacy apply/process materialized inputs with explicit rawResponse text (the null/omitted legacy reference sentinel is refused): metadata remains unknown/absent with no fabricated pages/limits. Recognized new collections require evidence. Failed/not_queried/no_record describe a completely submitted new command and are not partial reference reuse.

Existing natural keys are explicitly rejected with `collection_already_exists`; this does not implement or change public reuseExisting. W1b/W2b/W3b own preflight/preview/ref/result adapters; W4b/W4c own natural-key partial/reference reuse and last_collected_at updates, assignment revisions/merge, 113 material and receipt composition. Those owners must retain original query/evidence text at their ingestion boundary, supply explicit decisions and consume the output references. Public compatible routing still waits for W/R/H/C/X acceptance. No source writer or existing import branch is deleted, and no schema is added.

Real history, public cutover, complete W4 and #706 remain unaccepted/UNRUN. Three inherited HTTP baseline FAIL and #705/B409 remain unchanged.
