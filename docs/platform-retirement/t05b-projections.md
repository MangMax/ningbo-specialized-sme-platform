# T05b offline observation projections and canonical version archives (#715)

Run only on a frozen synthetic/isolated source and a target which has completed accepted T04 and T05a. This tool is upgrade-only; nothing in server/lib imports it. Node24, existing dependencies and 8GiB available disk on both filesystems are required.

```sh
node upgrade/run-projections.mjs FROZEN_SOURCE EXISTING_T05A_TARGET NEW_EVIDENCE_DIRECTORY T05B_RUN_ID T05A_RUN_ID T04_RUN_ID 100
```

Create the evidence directory first. Outputs use exclusive-create; restart with the same run IDs and a fresh output directory. `source-manifest.jsonl` and `target-manifest.jsonl` contain all PKs/cells in schema/PK order, storage classes and original SQLite byte hex (plus binary REAL bits). `receipt.json` binds source and target manifests. These are evidence, never runtime business fallbacks.

`t05b-source-projections-v1` has separate observation and version cursors. It revalidates T04/T05a before its first write. Source file/schema/full-cell manifest and prerequisite run IDs are immutable bindings. Each immediate transaction inserts a batch of source-specific projection rows or canonical references and advances its phase checkpoint plus a target digest. The target digest covers every application-table cell, other migration runs, and all phase checkpoints; its own digest checkpoint is excluded to avoid recursion. Resume refuses source, schema, transform, prerequisite, checkpoint or target drift. Full manifests are intentionally an offline safety cost, not a runtime/performance optimization. Trusted synchronous callbacks share the original retained T04 fd/SQLite guard; no source descriptor is reopened or closed during hash, transfer or CLI output.

Every observation gets exactly one row in the appropriate existing source table, even verified observations sharing one version and observations with raw-only or not_indexed content. Version-owner rows stay byte-identical. Source-specific content fields use parseApplyRecord, parseBusinessProcess or parseRecognizedRecord. Independently, the seven normalization fields retain stored input kind, old comparison value, parsed process input kind/value, reconciled value and conflict. Recognized never runs processFactsFromRow, and its stored year never becomes maintenanceYear. The original source_relation_key and identity conflict stay untouched. Runtime withArchiveProcessFacts supplementation remains the responsibility of the downstream source reader: only a modeled nonnull version value without that observation's field conflict may supplement. This tool adds no reader or positive-decision shortcut.

Row title kind and untrimmed text/JS String(number)/boolean0-or-1 are separate from trimmed display titleRaw. Thus SQL boolean extraction and JS rejection, numeric2 and text` 2 ` remain distinguishable. NULL raw is absent; malformed UTF-8/JSON or a non-object JSON root is invalid, with unavailable basis. Original TEXT/BLOB/empty/NULL bytes remain sealed in T02. No valid business object is fabricated for invalid input. Existing source parser error/unknown behavior stays explicit; a legacy process year outside the schema's safe-integer range refuses as unrepresentable rather than silently normalizing it.

Recognized captured fidelity is copied exactly from the original version projection, including NULL/false/empty/whitespace. Without a captured version fidelity field it stays NULL, even when raw-only normalized fields can be parsed. New observation projection created_at uses the original relation created_at as deterministic provenance, not a claimed indexing/verification time. All original observation indexing metadata is untouched.

Canonical archives retain the original SQLite canonical_raw_json storage class and bytes, hash algorithm/content hash, IDs and version fields. Original source version refs must match target owner/field/archive ID/seal and every archive metadata cell; length and SHA are recomputed from bytes on both sides. A target-only existing ref must have valid metadata and exactly matching bytes. New values use existing T02 typed canonicalRawJson refs; seal then canonical_archive_id binding occurs with the version checkpoint in one transaction. The old raw column remains. Ref payload similarity never excuses an ID or metadata mismatch.

T05c still owns final observation PK/FK promotion, relation_id removal and old T02 JOIN retirement. Real historical migration, runtime readers/writers, deletion, full migration and public/production acceptance remain UNRUN. A parent independent merger must accept this candidate. #705 performance FAIL and B409 remain unchanged; all raw failures and synthetic fixtures are retained outside Git.
