# W4b: explicit target replay and reference reuse

`writeCollectionTarget` in `lib/platform/collection-target-command.ts` is an internal synchronous 71607 command. It accepts original query/evidence text and the existing complete-new-collection command fields. New coordinates invoke `writeNewCollectionTarget`; that entry point remains new-only, including its legacy null-response refusal. Legacy rdjb and insert metadata now use the original public optionalString/default rules, while the original request bytes remain archived. Existing coordinates do not consume the submitted assignments or creation timestamp. This does not wire HTTP, MCP or workers, or change the 716 guard.

Collection planning uses typed interface/queryKey/rdjb/queriedAt with the public optionalString rule. The shared staged/persisted comparator runs against that planning source. Transaction recheck uses original queryKey/queriedAt plus optionalString(rdjb), matching writePlatformQuery; when this selects another existing collection it must independently pass the same comparator before any content write. Both owners use one target source adapter. Explicit references reject a missing normalized source and may reuse it when no exact-original collection exists; an existing exact-original source must independently pass the comparator. References never create collections or observations. Original coordinates are not rewritten. Observation membership uses typed collectionId/sequenceNo. Query/relation references come exclusively from their separate alias tables. No runtime upgrade import or old query/relation access is introduced.

The public planner and target share `query-replay.ts` for immutable comparison and `query-evidence.ts` for the existing evidence-envelope gate. Staged public sources retain their original insert defaults. Callers compose multiple target commands inside one transaction; every invocation rechecks persisted facts inside a nested savepoint. Earlier staged writes roll back if the enclosing transaction fails.

Explicit own properties remain assertions: omitted values are not clears. Only apply/process without evidence use the existing NULL/omitted rawResponse reference sentinel; recognized does not. Explicit reuse and legacy reference modes allow row subsets but never add sequence numbers. Ordinary materialized replay retains the original row set. Supplied source fields use the original source normalization; ownership and verification decisions remain in their separate workflows.

Sealed collection/observation archives are read only to verify immutable original payloads. New target rows use the original request archive; migrated rows use their sealed `t05a-sqlite-cells-v1` original snapshot. Archive storage, length and SHA are checked. These JSON originals do not choose collection membership or current assignment. Exact typed source_relation_key is retained, including NULL/empty/whitespace; original typed keys are never overwritten. New-command replay uses the old public insertion normalization for its key assertion; migrated rows use their actual original stored key. Independent public oracles cover both lifetimes.

An ordinary full raw assertion can index an existing paired not_indexed observation or complete its missing version projection through the source-owned content routines extracted from the three accepted writers. It preserves observation/collection/alias IDs, original bytes, existing fingerprints, assignment revisions and historical source-fidelity unknowns. A newly indexed observation gets an actual indexing timestamp, not an invented collection/decision time. Explicit reuse and omitted raw never bootstrap. A missing observation-owned source-fidelity row is a T05b prerequisite failure (projection_missing), not permission to infer its old capture state from raw or the latest shared version. Such a row requires trusted restoration/revalidation. Source conflicts remain errors; content repair and final observation update share the caller savepoint.

Replay returns collection/query alias and observation/relation alias pairs. Its `item` retains platform_query ref, skipped, rowsWritten=0, reuseExisting and canonicalProjection detail. Projection summaries distinguish newly completed content from reused observations. Completing a migrated not_indexed branch counts as observationCreated in the legacy projection summary, matching the original public index bootstrap; the target observation ID itself is retained. The new-coordinate result retains the #721 shape plus reused=false.

This command never updates last_collected_at. The existing `reuseCollectedPlatformResult` path requires a separate actual fresh complete live result, scope/content equality, latest query and full owner/projection coverage before advancing it. Replaying an old coordinate supplies no such new collection time. A genuinely new queriedAt passed to this command creates another collection/observation even when the version content is identical.

W1b/W2b/W3b still own public source adapters, result/preview integration and the public gate. W4 assignment/correction/merge, 113 capture and receipt orchestration remain separate. Reader cutover, real-history acceptance, complete W4/#706 and physical retirement are not established here. The three inherited HTTP expectation failures and #705/B409 performance FAIL remain unchanged.

The post-C replay adapter calls the accepted fingerprint verifier separately for every selected planned and exact-original observation. It never uses request existence to choose a hash scheme. Paired not_indexed references call C in reference mode and create nothing; ordinary complete raw replay calls bootstrap only after original payload, row-set and source-owner checks. Indexed mapping checks include identity/content/key source, record/version, original rule/hash and revision1. Current assignments remain independent.

To retain the original missing-version-projection behavior, the shared verifier has an explicit `allowMissingVersionProjection` read option. Default callers remain strict. Replay comparison permits only an absent derived version projection; any present projection still receives full equality checks. Basis, source archives, observation projections, mapping, original hash/rule and revision1 are always required. Ordinary content completion then runs strict verification before returning. No missing basis or uncaptured scheme is accepted. Complete archive FK inventory uses one SQLite catalog query; no legacy entity data is read.

This implementation candidate combines the previously rejected replay work with F1/F2 repair and accepted C. Bringing the old commit into this private branch does not accept that original candidate. The original four review FAILs remain historical; new evidence is under `w4b-replay/post-capture/`.
